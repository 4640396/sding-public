# 2026-07-17 Project Evolve 规则完善决策记录

> [!important] 状态边界
> 本文记录用户已经接受的 Project Evolve 规则选择。`accepted` 表示规则已经决定；实际实现和验证以 [[2026-07-17 Project Evolve Skill 规则完善与验收记录]] 为准。

## 已接受决策

1. 采用七步生命周期：收集、分析、决策、实施、验收、沉淀、归档；查询、总结、复盘和维护作为辅助动作。
2. “继续下一阶段”不构成实施授权，应先检查上一阶段验收、未决事项和下一阶段范围。
3. 验收可修复阶段范围内、不改变 accepted 设计的小缺陷；涉及产品行为、数据模型、公共接口、安全边界或阶段范围变化时转入决策。
4. 未确认但完整且需要长期追溯的 `draft` 可以进入项目目录；零散、正在编辑或等待确认的材料进入工作台项目子目录。
5. 用户明确委托 Agent 在限定范围内代选时，可记录为 `accepted`；费用、法律、真实支付、生产数据和重大安全事项不得仅凭一般委托代选。
6. 建立按改动类型划分的最低验证矩阵。
7. 强制区分实现完成、验收通过和生产就绪。
8. 验收记录必须包含环境、命令或操作、结果、未执行原因和源码版本；优先 Git commit，无 Git 时使用关键文件哈希。
9. Frontmatter 统一使用 `sources`；增加稳定 `project_id`，`project` 使用项目索引中的规范显示名。
10. `verified` 只保证明确标出的事实和验证结果，不自动覆盖建议、计划或未验证边界。
11. 沉淀结束执行导航、链接、替代关系和状态检查；只有确需导航时才修改项目索引。
12. Graphify 过期条件采用模块、时间、路径和源码冲突标准；`--reuse-graph` 不足时退回源码，不自动刷新。
13. 涉及支付、第三方 API、法规或版本能力时，实施前优先核验官方资料；无官方证据时保留为未验证项。
14. Skill 维护增加当前规则版本、典型提示词回归用例，以及 Skill、说明文档和界面元数据的同步检查。

## 未授权事项

本次决策只授权维护、验证和沉淀 Project Evolve Skill，不授权修改其他项目代码、连接真实外部服务、刷新 Graphify 索引或执行生产动作。
