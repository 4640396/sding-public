# 2026-07-25 知识库换机迁移与双机同步阶段总结

## 阶段结论

知识库已在新电脑完成 GBrain/Graphify 基础环境恢复、D 盘路径迁移和双机便携路径改造。本机 Vault、GBrain、Evolve、筛选镜像和当前项目路径均可用。

旧电脑恢复流程已经形成，但尚未在旧电脑实际执行。Git 仓库、远程仓库和自动同步尚未实施。

Graphify 在本阶段只完成 CLI 与 Codex Skill 安装，没有生成项目代码图谱；这不影响 GBrain 全文检索和原始 Markdown 核验。

## 已完成

### 本机恢复

- uv 与 Graphify CLI 已安装并可识别。
- GBrain 与 Evolve 已注册为用户级 Codex Skill 目录联接。
- GBrain 确定性筛选镜像已在操作系统缓存目录重建。
- bootstrap 的 uv 工具路径已改用 `%USERPROFILE%`，不再依赖异常的 `USERNAME` 值。

### 路径迁移

- 当前工作根目录为 `D:\works`，用户级 `WORKS_ROOT` 已保存。
- DCS、IoT、3x-ui、initdata 和 Vault 的当前入口已完成 D 盘核验。
- 当前导航、部署命令、工具入口和仍会执行的方案统一改用 `$env:WORKS_ROOT`。
- 历史实施、验收和旧输出证据继续保留当时的 C/D 盘绝对路径。

### 双机便携性

- GBrain 不再写死规范 Vault 的盘符，而是从活动 Skill 的物理目标定位 Vault。
- bootstrap 在 `WORKS_ROOT` 缺失时，仅从 `<WORKS_ROOT>\doc\sding` 结构安全推导并保存。
- 显式目录不存在或与当前 Vault 不匹配时，bootstrap 明确失败，不静默使用错误目录。
- bootstrap 一次注册 GBrain 与 Evolve；`-CheckOnly` 只检查而不写环境变量。

## 验收证据

- Evolve 与 GBrain 均通过 Skill Creator 官方 `quick_validate.py`。
- `WORKS_ROOT` 的自动推导、用户级变量、目录不存在和目录不匹配四类分支均已测试。
- 正常 bootstrap 已成功完成双 Skill 联接核对和 GBrain 镜像刷新。
- 本机 `$env:WORKS_ROOT` 展开后的 Vault、DCS、IoT、3x-ui 和 initdata 路径均存在。
- 活跃 Skill 中固定 `C:\works` 或 `D:\works` 引用为 0。

## 尚未实施

- 当前 `.git` 是空目录，不是有效 Git 仓库。
- 尚无 `.gitignore`、初始提交、远程仓库或双机同步流程。
- 旧电脑尚未同步 Vault，也未运行新版 bootstrap。
- `%LOCALAPPDATA%\Graphify\projects` 尚不存在，项目代码图谱需要在实际代码关系分析时按项目生成。
- Ollama 与 internal Markdown 语义图谱尚未配置，不影响当前全文检索能力。

## 风险与边界

- Vault 当前存在 `sensitivity: confidential` 笔记。按照根治理规则，不能在没有新决策的情况下把完整 Vault 推送到 GitHub、Obsidian Sync 或其他外部服务。
- 双机若同时修改同一笔记，Git 或文件同步工具都可能产生冲突；正式启用同步前需要确定主工作流。
- 部分 PowerShell 启动环境仍可能报告个人 `profile.ps1` 被执行策略阻止；使用 `-NoProfile` 运行 bootstrap 不受影响。
- 本阶段没有连接生产系统，没有部署应用，也没有修改 Graphify 项目缓存。

## 推荐下一步

1. 重启当前电脑的 PowerShell 和 Codex，确认新会话读取 `WORKS_ROOT=D:\works`。
2. 确定同步边界和传输方式：
   - 保持 confidential 仅在自有设备本地流转；或
   - 单独审查并变更外部同步治理规则。
3. 确定后再初始化 Git、创建 `.gitignore`、建立受控远程并完成首次提交。
4. 在旧电脑把 Vault 放到 `C:\works\doc\sding`，运行新版 bootstrap，验证自动得到 `WORKS_ROOT=C:\works`。

以上推荐尚未形成 accepted 同步决策，也不代表 Git 或旧电脑恢复已经实施。
