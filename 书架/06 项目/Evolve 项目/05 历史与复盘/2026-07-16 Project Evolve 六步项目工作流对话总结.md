# 2026-07-16 Project Evolve 六步项目工作流对话总结

## 本次对话结论

用户无需记忆 YAML 状态、完整技术提示词或每个工具的调用顺序。当前使用 `$evolve` 时，只需围绕六个中文动作表达意图：

```text
分析 → 决策 → 沉淀 → 实施 → 验收 → 总结
```

Skill 负责按任务类型选择 GBrain、Graphify、源码核验、测试和 Obsidian 写入流程。遇到真实支付、生产部署、删除数据等高风险动作时，仍需用户单独明确授权。

## 六个动作

### 分析

目的：了解项目背景、历史约束、当前代码和影响范围。

```text
$evolve 分析这个需求
```

- 默认不修改代码。
- 知识背景使用 GBrain。
- 架构、调用链和影响范围确有必要时才使用 Graphify。
- Graphify 默认复用现有图谱，不无条件刷新。

### 决策

目的：把会影响设计或实施的选项交给用户确认。

```text
$evolve 列出需要我决策的事项
```

用户可直接在 Obsidian 工作台的待决策清单中勾选或填写。完成后只需说：

```text
$evolve 我已经完成决策，请检查并沉淀
```

- 已明确的选择形成正式决策记录，通常使用 `status: accepted`。
- 未勾选或证据不足的事项继续保留为待决策或外部待验证。
- “已接受”只表示决定采用，不代表功能已经实现。

### 沉淀

目的：按 GBrain 治理规则把分析、事实、决策或实施结果写入 Obsidian。

```text
$evolve 沉淀刚才的分析
```

- 未确认的分析和方案通常记录为 `draft`。
- 重新核验原始源码并记录来源的当前事实，才可考虑 `verified`。
- 正式接受但尚未实施的决定使用 `accepted`。
- 用户不需要记住英文状态，Skill 应自动分类并在无法安全判断时说明。

### 实施

目的：依据已确认的方案和决策修改代码。

```text
$evolve 实施第一阶段
```

- 每次只实施一个范围明确的阶段。
- 先读取项目目录中的当前事实、正式决策和阶段计划。
- 工作台是否已经完全归档不阻止实施，但正式决策记录应作为依据。
- 不自动扩展到真实支付或生产部署。

### 验收

目的：验证某阶段的数据库迁移、集成、测试和关键用户流程。

```text
$evolve 验收第一阶段并沉淀
```

这句短提示应让 Skill 自动读取实施记录，执行本地可用的迁移、测试和冒烟验证，发现问题时修复并复测，然后沉淀实际结果。

“验收”不自动授权连接真实支付、真实 SMTP、真实 3x-ui 或生产环境。外部系统和生产动作需要更明确的用户许可。

### 总结

目的：区分实际完成内容、验证证据、未验证项、遗留风险和下一步。

```text
$evolve 总结并沉淀
```

验收已经包含完整总结和沉淀时，不必重复执行一次总结。

## 推荐的最短循环

```text
$evolve 分析这个需求
$evolve 我已经完成决策，请检查并沉淀
$evolve 实施第一阶段
$evolve 验收第一阶段并沉淀
$evolve 实施下一阶段
```

如果分析阶段还没有生成待决策清单，可在分析后补充：

```text
$evolve 列出需要我决策的事项
```

## 工作台的角色

`书架/01 工作台` 保存正在处理、等待确认或尚未收口的材料。它不是稳定知识区。

- 改造分析可在实施期间继续保留在工作台。
- 待决策清单在用户确认后应形成项目目录中的正式决策记录。
- 正式记录生成后，原始清单不会自动删除，这是为了保留过程和避免误删。
- 完成收口时，可把原清单标记为 `deprecated`，使用 `superseded_by` 指向正式决策记录，再移入归档；不直接删除历史。

工作台中的复选框表示用户选择了选项，但只有正式决策记录形成后，后续实施才有清晰、可追溯的依据。

## 3x-ui-sub 本轮状态示例

本次对话中，3x-ui-sub 用户中心与支付改造已经经历以下步骤：

1. 完成项目背景、历史材料、当前代码和影响范围分析。
2. 将改造分析、待决策清单和当前代码事实分层沉淀。
3. 用户在工作台确认支付渠道和注册方式等选项。
4. 项目目录中形成 `status: accepted` 的用户中心与支付决策记录。
5. 第一阶段完成实施，并生成第一阶段实施记录。
6. 下一步应先验收第一阶段，再进入第二阶段的套餐、订单、权益和模拟支付闭环。

推荐下一句：

```text
$evolve 验收第一阶段并沉淀
```

## 状态词无需用户记忆

用户只需表达自然语言意图：

| 用户意思 | Skill 应采用的治理处理 |
|---|---|
| 先记下来，尚未确认 | `draft` |
| 已核验，可作为当前事实 | `verified` |
| 已决定采用，但尚未实施 | `accepted` |
| 以后处理 | `backlog` 或待决策清单 |
| 已被正式记录替代 | `deprecated` + `superseded_by` |
| 包含机密内容 | 按 `sensitivity: confidential` 的本地安全边界处理 |

`confidential` 是敏感级别，不是实施状态。它可以与 `draft` 等状态同时存在。
