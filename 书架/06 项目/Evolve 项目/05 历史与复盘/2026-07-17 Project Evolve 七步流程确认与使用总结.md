# 2026-07-17 Project Evolve 七步流程确认与使用总结

> [!note] 状态边界
> 本文是本次对话的使用总结，保留为 `draft`。稳定执行规则以 [[日常维护流程]] 和 [[Evolve 跨项目演进工作流 Skill]] 为准。

## 核心结论

Project Evolve 的完整项目闭环是：

```text
收集 → 分析 → 决策 → 实施 → 验收 → 沉淀 → 归档
```

这七步是完整生命周期，不表示每个任务都必须机械执行全部步骤。Project Evolve 应根据用户请求选择最小必要流程。

## 常见裁剪方式

| 场景 | 建议流程 |
|---|---|
| 只了解问题或项目背景 | 分析 |
| 简单且明确的局部修改 | 分析 → 实施 → 验收 |
| 新功能或较大改造 | 分析 → 决策 → 实施 → 验收 → 沉淀 |
| 已经完成开发，需要确认质量 | 验收 → 沉淀 |
| 整理旧材料 | 收集 → 沉淀 → 归档 |
| 继续下一阶段 | 分析或决策 → 实施 → 验收 |

## 辅助动作

以下动作会出现在七步流程中，但不单独作为主流程阶段：

- **GBrain 查询**：查找 Obsidian 中的项目背景、历史记录和约束。
- **Graphify 分析**：只有代码架构、依赖、调用链或影响范围确实影响判断时才使用。
- **总结**：区分完成内容、验证证据、未验证项、风险和下一步；只有用户要求沉淀时才写入 Vault。
- **复盘**：通常属于沉淀或归档。
- **维护**：定期清理收集箱、工作台、失效链接和被替代内容。
- **部署与迁移**：属于实施；生产环境、真实第三方系统和数据删除仍需单独授权。

## 用户需要记住的最短提示词

日常使用只需记住：

```text
分析、决策、实施、验收、总结沉淀
```

“收集”和“归档”通常由 Project Evolve 根据材料当前状态处理，不要求用户每次显式说明。

可直接使用：

- `$evolve 分析 <项目或需求>`
- `$evolve 列出需要我决策的事项`
- `$evolve 我已经完成决策，请检查并沉淀`
- `$evolve 实施第一阶段`
- `$evolve 验收第一阶段并沉淀`
- `$evolve 总结并沉淀`
- `$evolve 继续下一阶段`

## 不变的边界

- “只分析”不授权修改代码。
- “总结”不自动写入 Obsidian，必须同时提出“沉淀”。
- `accepted` 表示已经决定但不代表已经实施。
- `verified` 必须有原始资料、源码、配置或测试证据支撑。
- Graphify 是按需工具，不是每次流程的必经步骤。
