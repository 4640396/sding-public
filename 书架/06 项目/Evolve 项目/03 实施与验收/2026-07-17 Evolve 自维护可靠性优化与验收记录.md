# 2026-07-17 Evolve 自维护可靠性优化与验收记录

## 结论

Evolve 已完成一次基于真实维护记录的自维护可靠性优化。此次没有改变七步生命周期、决策权限或高风险授权边界，主要补齐组合授权识别、受保护路径预检、部分失败恢复、历史证据识别、验收范围隔离和验证证据顺序。

## 分析发现

近期规则维护、独立项目拆分和 Skill 更名暴露出以下可复用问题：

- “先分析，可以优化就直接实施”缺少明确的组合授权解释。
- Skill 与全局入口可能位于受保护或 Vault 外路径，多位置迁移不能假设为原子操作。
- 迁移部分失败后若继续依据原计划，可能误判真实文件位置。
- 历史记录中的旧名称会被简单全文搜索误判为当前残留。
- 全 Vault 严格检查可能命中与本次无关的既有特殊链接。
- 无 Git 环境缺少明确的证据回退方式。
- 验收记录应在取得验证结果后再标记 `verified`。
- `draft` 进入正式项目目录的条件需要与 Vault 根规则进一步收口。

## 实际修改

- 规则版本更新为 `2026-07-17.2`。
- Skill description 增加维护、迁移和重命名 Evolve 自身的触发语义。
- 增加“分析并在可优化时直接实施”的组合动作规则。
- 明确完整 draft 只有在用户要求沉淀且形成长期项目工件时才进入项目目录；处理中材料仍放工作台。
- 自维护时强制使用 Skill Creator，并检查文件夹名、frontmatter、界面提示和调用名一致。
- 增加路径、反向引用、全局入口、权限和受保护目录预检。
- 增加多位置迁移的执行顺序和部分失败后的重新盘点规则。
- 区分当前引用与历史证据，不再用“旧名称全局零出现”作为唯一验收标准。
- 链接验收先限定本次范围，全 Vault 既有问题单独报告。
- Git 不可用时改用准确文件清单和必要的关键文件哈希。
- 明确先验证、后创建 verified 验收记录。
- 回归用例增加组合优化、Skill 重命名、历史名称和迁移失败场景。
- 同步 [[Evolve 跨项目演进工作流 Skill]]。
