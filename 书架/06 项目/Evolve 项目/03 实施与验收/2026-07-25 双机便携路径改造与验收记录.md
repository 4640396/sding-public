# 2026-07-25 双机便携路径改造与验收记录

## 目标

同一份 Vault 需要同时支持：

- 新电脑：`D:\works\doc\sding`
- 旧电脑：`C:\works\doc\sding`

当前导航、执行命令和 Skill 不再写死盘符。历史实施与验收记录继续保留当时的真实绝对路径。

Graphify 与本次路径配置无关，未生成或刷新项目代码图谱。

## 路径规则

Windows 当前工作根目录统一表示为 `$env:WORKS_ROOT`。

bootstrap 按以下顺序解析：

1. 使用有效的进程级 `WORKS_ROOT`；
2. 否则使用有效的用户级 `WORKS_ROOT`；
3. 两者都缺失时，仅在 Vault 符合 `<WORKS_ROOT>\doc\sding` 时自动推导；
4. 显式目录不存在、目录与当前 Vault 不匹配或无法安全推导时，立即停止并输出明确错误。

正常 bootstrap 会把最终值保存到用户环境；`-CheckOnly` 只显示解析结果，不修改配置。

## 实施结果

- GBrain Skill 改为从当前 Skill 的物理目标向上定位规范 Vault，不再写死盘符。
- GBrain bootstrap 自动解析并保存 `WORKS_ROOT`。
- bootstrap 一次注册 GBrain 与 Evolve 两个用户级 Skill 目录联接。
- Evolve 规则版本更新为 `2026-07-25.2`，要求 Windows 当前路径使用 `WORKS_ROOT`，历史证据保留原路径。
- Evolve 回归用例、GBrain 运维说明和换机手册已同步更新。
- DCS、IoT、3x-ui 的当前导航、部署命令、Graphify 命令、工具入口和仍会执行的迁移方案已改为 `$env:WORKS_ROOT`。
- 本机用户环境已保存 `WORKS_ROOT=D:\works`。

## 验收证据

### Skill 与脚本

- Skill Creator `quick_validate.py`：
  - Evolve：`Skill is valid!`
  - GBrain：`Skill is valid!`
- `WORKS_ROOT` 缺失：从当前 Vault 成功推导 `D:\works [Inferred]`。
- 用户级变量存在：成功解析 `D:\works [User]`。
- 显式指向不存在目录：脚本失败并报告目录不存在。
- 显式指向存在但不包含当前 `doc\sding` 的目录：脚本失败并报告与当前 Vault 不匹配。
- 正常 bootstrap：成功完成双 Skill 联接核对和 GBrain 镜像刷新。

### 当前入口

- GBrain 全局入口指向 `$env:WORKS_ROOT\doc\sding\.agents\skills\gbrain`。
- Evolve 全局入口指向 `$env:WORKS_ROOT\doc\sding\.agents\skills\evolve`。
- 活跃 Skill 中固定 `C:\works` 或 `D:\works` 引用为 0。
- 固定 D 盘路径只保留在上一轮新设备迁移验收记录中，属于历史事实。

## 旧电脑恢复步骤

将 Vault 同步或克隆到 `C:\works\doc\sding` 后，在 Vault 根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .agents\skills\gbrain\scripts\bootstrap_windows.ps1
```

脚本会推导并保存 `WORKS_ROOT=C:\works`，注册 GBrain/Evolve，确认 uv 与 Graphify，并重建本机 GBrain 镜像。完成后重启 PowerShell 和 Codex。
