# 2026-07-17 Evolve 知识落点约束与验收记录

## 结果

Evolve 规则已更新至 `2026-07-17.4`。知识落点硬约束适用于所有现有和未来项目，不限于 DCS，也不受代码仓库所在磁盘、远程工作区或目录结构影响。

## 范围澄清

- DCS、IoT、3x-ui、GBrain、Evolve 及以后新增项目执行同一规则。
- 任何项目的知识工件统一进入 `sding` 规范 Vault 的收集箱、工作台或对应项目目录，不跟随代码目录。
- 尚未建立 Vault 项目入口的新项目，先报告缺少入口并按治理规则进入收集箱或工作台，不在代码目录自建知识库。

## 已实施规则

- 写入前从规范 Vault 项目索引定位目标项目，不把当前源码工作区当作知识沉淀位置。
- 需求分析、决策、执行手册、排查记录、验收证据和仅供人工执行的 SQL 归入 Vault；Vault 内 SQL 使用 Markdown `sql` 代码块。
- 应用直接消费的源码、配置和数据库迁移脚本继续留在代码仓库，Vault 只记录来源与验证结果。
- 已有同主题知识时优先更新或链接现有工件，不创建并行副本。
- 收口时反查源码工作区和 Vault，并检查项目索引入口及临时目录引用。
- 无法判断工件属性时保持原位并报告，不复制到两个位置。

## 验收证据

- 验证环境：Windows PowerShell，Vault 根目录 `C:\works\doc\sding`。
- 官方校验：使用 Skill Creator 的 `quick_validate.py`。
- 首次执行：捆绑 Python 缺少 `PyYAML`，校验未启动；这是运行环境依赖问题，不是 Skill 结构失败。
- 复测执行：设置 `PYTHONUTF8=1`，使用 `uv run --with pyyaml` 运行同一官方校验脚本。
- 复测结果：`Skill is valid!`，退出码 `0`。
- 内容回归：规则版本、知识落点章节、Vault SQL 规则、源码与知识工件边界、收口反查要求和 DCS 场景回归用例均已存在。
- 界面元数据：名称和调用仍为 `Evolve` / `$evolve`；短描述与默认提示已同步为所有项目知识统一进入规范 Vault。
- `2026-07-17.4` 复测：官方校验再次返回 `Skill is valid!`；通用项目路径、现有项目、新项目缺少入口、任意代码位置和界面提示等内容回归全部通过。
