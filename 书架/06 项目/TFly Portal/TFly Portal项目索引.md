# TFly Portal项目索引

## 项目目标

在不改变3x-ui原有通用订阅的前提下，为 Clash/Mihomo 用户提供带策略组和分流规则的独立订阅地址，并通过自定义订阅页面完成复制和客户端导入。

## 当前组成

- `portal/`：Go 服务端渲染的用户中心与基础管理后台，模板和静态资源嵌入同一个二进制。
- `gateway/`：Go 实现的订阅转换网关，读取 3x-ui 原生 Clash YAML，保留节点字段并生成策略组与规则。
- Nginx：为 Portal 与 Gateway 提供公网 HTTPS 入口，Go 服务仅监听本机回环地址。

## 代码位置

```text
$env:WORKS_ROOT\tfly-portal\gateway
$env:WORKS_ROOT\tfly-portal\portal
$env:WORKS_ROOT\tfly-portal\releases
```

知识库只保存架构、部署结论和排障记录，不保存构建缓存、二进制源码副本或真实订阅凭据。

## 当前状态

- 3x-ui 面板和 SSH 已收口到 Tailscale 私网；公网面板端口和公网 SSH 已验证不可达。
- UFW 已启用默认拒绝入站策略，仅放行 Tailscale、Nginx 和当前节点入站所需端口。
- PostgreSQL 已确认为当前 3x-ui 生产数据后端；数据库、证书和 Xray 配置已建立受控备份与回滚点。
- 陈旧的 `13005` Xray 入站已停止监听并从重生成配置中清除；当前证据不支持恶意创建。
- 订阅网关因运行进程未重读环境文件而返回 `502`，重启服务后真实转换请求恢复 `HTTP 200`。
- Portal 第一版已完成账号与真实邮件、服务绑定、流量与剩余时长展示、Portal 订阅 Token 和独立管理员控制台；继续使用 Go 服务端渲染，不单独部署前端。
- 客户邀请核心功能与 3x-ui 新版 `settings` 对象响应兼容修复已经生产发布；systemd、本机和公网健康检查通过，后台候选服务账号读取恢复。真实邀请闭环与上游数据一致性仍需按发布手册做人工业务验收。
- 邀请候选账号的深色下拉样式与“备注 · 服务账号”展示已完成测试和 Linux 构建，当前尚缺生产发布成功回执，不记为已上线。
- 账号设置、自助开通申请、邀请检索、用户筛选分页、邀请投递状态和审计日志已完成实现与本地核心验收；用户首页账户操作区及设置 Tab 页面已完成界面回归。整批改动尚缺生产发布和真实邮件人工验收回执，不记为已上线。
- 用户中心订阅就绪区、服务进度、流量与到期卡片已完成布局收敛；有限额度和不限流量状态均按 3x-ui 真实数据实现并通过本地浏览器验收。当前发布包尚未取得生产发布回执，不记为已上线。
- 已建立一键发布脚本和独立 SSH 部署密钥；密钥认证验证为 `key-auth-ok`，后续发布无需反复输入服务器密码，私钥不进入仓库或知识库。
- 根目录 `override.yaml` 已成为 Gateway 唯一完整 Mihomo 模板源；Gateway 只注入当前用户 `proxies`。Portal 与 Gateway 已合并使用 `publish-tfly.ps1`，交互输入 `1` 或 `2` 选择部署组件，生产替换仍要求 `DEPLOY` 二次确认。源码测试、静态检查与 Linux 交叉编译已通过，但本次改动尚未取得生产发布和真实客户端更新订阅回执。
- Clash/Mihomo 与通用节点订阅已拆分为两个独立 Portal Token，可以分别生成和轮换；用户侧路径为 `/clash/{portalToken}` 与 `/{portalToken}`，旧 `/sub/{portalToken}` 明确返回 `404`。本地单元测试和 PostgreSQL 集成测试通过，尚缺生产发布与真实 v2rayNG、Mihomo 客户端回归。
- 公开订阅子域名已从 `/clash/` 直连 Gateway 与根路径 `404`，切换为整个站点经 Nginx 进入 Portal；公网 `/healthz` 已通过 Cloudflare 返回 `HTTP/2 200`。
- Gateway 继续作为 Portal 的回环上游独立运行；是否在稳定观察后合并进 Portal 仍是后续架构决策，不影响当前产品入口统一。
- 备用节点已完成 Tailscale 私网管理、MagicDNS 受信任证书、UFW 收口和官方多节点注册；主节点可通过标准 CA 校验与专用 API Token 远程管理。
