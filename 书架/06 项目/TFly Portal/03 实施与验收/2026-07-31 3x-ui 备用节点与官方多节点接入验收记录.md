# 2026-07-31 3x-ui 备用节点与官方多节点接入验收记录

> [!summary] 阶段结论
> 备用节点已完成 Tailscale 私网管理、受信任 HTTPS、默认拒绝入站防火墙和 3x-ui 官方多节点接入。主节点可以通过 Tailscale、系统 CA 校验和专用 API Token 控制备用节点，并已远程下发一个 VLESS + REALITY + Vision 测试入站。Shadowrocket 在服务端默认最低客户端版本下无法转发，但将最低版本临时降低到 1.8.0 和 1.8.5 后可用；兼容上限和最终安全取舍仍未确认，因此本阶段不能标记为生产就绪。

## 范围与安全边界

- 本记录只保存角色、版本、端口用途、验证结果和未决风险。
- 不保存真实公网 IP、Tailnet 私有地址、完整 MagicDNS 名称、面板随机路径、API Token、UUID、订阅 ID、REALITY 私钥、Short ID 或完整分享链接。
- 备用节点公网只用于代理数据面；面板、SSH 和节点控制面只走 Tailscale。
- 多节点与防火墙可以降低单点暴露和管理面风险，但不能保证公网 IP 永不被过滤。

## 备用节点基线

- 操作系统实机确认为 Debian 12。
- Tailscale 已从官方 Debian 仓库安装，客户端版本和 `tailscaled` active 状态已验证。
- Windows 到备用节点的 `tailscale ping`、私网 TCP 22 和 Tailscale SSH 均成功。
- 3x-ui 已安装为 3.6.0，Xray 运行版本由主节点心跳读取并显示正常。
- 备用节点采用 SQLite，本地数据库中发现 16 条历史入站；用户确认这些备注均为自己过去创建的配置，不支持“恶意创建”判断。

## 历史数据处置

1. 在修改前备份备用节点 SQLite 数据库，并验证源文件与副本哈希一致。
2. 历史入站最初在界面操作后短暂停止，但数据库 `enable` 仍为 1，重启后再次监听。
3. 停止 3x-ui 后以事务方式将历史入站 `enable` 更新为 0，再启动服务。
4. 验证数据库启用入站数为 0，历史端口全部停止监听。
5. 没有删除历史用户或入站，因此仍可从备份或数据库回滚。

> [!important] 复盘
> 判断入站是否真正停用不能只看一次 `ss` 输出。必须同时核对数据库 `enable`、服务重启后的监听状态和 Xray 运行态；否则热更新或重启可能重新加载旧配置。

## 私有管理面与证书

- 备用面板端口统一为 2083，仅绑定备用节点 Tailscale 地址。
- 面板根路径严格 HTTPS 请求返回 404，随机管理路径可正常登录。
- 备用节点订阅服务 2096 已关闭，重启后仍未监听。
- 原公网 IP 证书只覆盖公网地址且有效期很短，不适合主节点通过 Tailscale 地址做长期标准校验。
- Tailnet 已启用 HTTPS Certificates，备用节点成功签发 MagicDNS 域名证书。
- 证书 SAN、有效期、证书文件 644 权限和私钥 600 权限均已验证。
- 3x-ui 面板已切换到该证书；备用节点本机与主节点均能在不使用 `-k` 的条件下完成 HTTPS 校验并获得预期 404。
- 主节点最初关闭了 Tailscale DNS；执行 `tailscale set --accept-dns=true` 后，MagicDNS 可解析备用节点并通过严格 TLS 访问。

> [!warning] 证书续期未完成
> 本轮只完成首次签发和面板切换，尚未建立证书自动续期、续期后重载 3x-ui、到期告警和续期失败回滚。证书自动化完成前不得把节点长期无人值守运行视为生产就绪。

## 防火墙验收

- 备用节点安装并启用 UFW。
- 默认策略为拒绝入站、允许出站、禁止 routed 流量。
- 启用前添加 Tailscale 接口和 Tailscale 直连 UDP 放行规则，并保持第二个 Tailscale SSH 会话在线。
- 启用后第二会话仍在线，Windows 验证私网 SSH 和面板可达，公网 SSH与历史代理端口不可达。
- 创建测试入站后仅额外放行 443/tcp。
- 当前主机防火墙的预期公开范围是 Tailscale 直连 UDP 与测试代理 TCP 443；面板、SSH、订阅端口和历史代理端口不对公网开放。

## 官方多节点接入

3x-ui 官方架构确认远程节点是另一套 3x-ui 实例，主节点通过 HTTPS 调用子节点 API，并支持 `verify`、`skip`、`pin` 和 `mtls` TLS 模式。本次采用：

- 管理地址：备用节点 MagicDNS 完整域名。
- 管理协议：HTTPS。
- TLS 模式：系统 CA 标准校验 `verify`。
- 认证：备用节点创建的专用、可撤销 API Token；未使用登录密码，也未在记录中保存 Token。
- 私网地址校验：节点表单明确允许 Tailscale 私有地址。
- 入站导入：选择“选定的入站”，未导入备用节点历史入站。

验收证据：

- 主节点测试连接成功，并读取到备用节点 Xray 版本。
- 节点保存后显示在线、心跳正常、延迟为低毫秒级、客户端初始数量为 0。
- CPU、内存、网络和运行时长图表可以从备用节点回传。
- 节点控制通信完全通过 Tailscale 和受信任证书，无需开放公网面板端口。

## 测试入站与客户端

主节点远程创建了一个仅部署到备用节点的测试入站：

- 协议：VLESS。
- 传输：RAW/TCP。
- 安全：REALITY。
- Flow：`xtls-rprx-vision`。
- 公网入口：备用节点独立、仅 DNS 的节点域名与 TCP 443。
- 分享地址：使用自定义公网节点域名，不使用节点的 Tailscale 管理地址。
- 嗅探：HTTP、TLS、QUIC；仅用于路由。
- 客户端：单个测试客户端，有限流量和单 IP 限制。

远程下发验证：

- 备用节点 SQLite 出现对应 443/VLESS 入站且状态启用。
- Xray 运行态监听 443。
- 备用节点数据库中的测试入站包含 1 个客户端，Flow 为 `xtls-rprx-vision`。
- 热更新后磁盘 `config.json` 曾未立即包含新入站，但数据库和 Xray 运行态均已生效；后续排查不能把磁盘生成文件当作唯一运行事实。
- 备用节点直接访问 Google 返回 HTTP 200，出站为 `freedom/direct`，排除了服务器公网出站故障。

## REALITY 目标复盘

- 初始目标使用 Microsoft 公网站点，Xray 运行日志明确警告该目标会提高服务器 IP 被封锁的可能性。
- 根据服务端内置目标扫描器重新选择 TLS 1.3、h2、X25519、证书匹配的其他目标。
- 保存后日志不再出现目标封锁风险警告，只保留最低客户端版本警告。
- 初始 REALITY 私钥曾出现在截图中，随后重新生成密钥对、Short IDs 和 SpiderX；暴露的旧值不得复用。

> [!warning] 目标不是永久配置
> “扫描显示可用”只证明当时 TLS 能力和证书匹配，不保证长期稳定或不会被过滤。应把 Xray 运行警告、目标可达性和实际网络结果纳入定期复核。

## Shadowrocket 兼容性诊断

已验证事实：

- Shadowrocket 为最新可用版本，导入配置包含 VLESS、TCP、REALITY、SNI、Vision、公钥和 Short ID。
- 公网 TCP 443 可达，服务端能看到来自客户端的 established 连接，但默认设置下无法通过代理访问 Google。
- 备用节点本机可访问 Google，且 Xray 出站配置正常。
- Xray 日志提示默认最低客户端版本为 26.3.27，其他客户端可能被拒绝。
- 将最低客户端版本临时设为 1.8.0 后 Shadowrocket 可以访问；提高到 1.8.5 后仍可访问。

尚未验证：

- Shadowrocket 能接受的最高 `minClientVer`。
- `26.3.26` 是否可用；对话结束前没有收到测试结果。
- 最终是否接受降低版本门槛，或改用能满足 26.3.27 默认门槛的客户端。

当前结论：兼容故障来自 REALITY 最低客户端版本门槛的证据较强，但最终门槛仍需继续测试。`1.8.5` 只是最后一个已验证可工作的值，不代表推荐生产值。
