# 2026-07-16 3x-ui-sub 用户中心第一阶段验收记录

> [!summary] 验收结论
> 第一阶段在真实临时本地 PostgreSQL 17.5 上完成数据库迁移和完整认证冒烟测试，验收通过。测试发现并修复了退出登录缺少审计记录的问题，修复后全量回归通过。真实 SMTP、真实 3x-ui、真实支付和生产部署未连接、未测试、未实施；第二阶段未开始。

## 1. 验收边界

本次验收仅覆盖：

- 临时本地 PostgreSQL 启动、迁移、查询和停止；
- development 日志邮件适配器；
- 注册、邮箱验证、登录、退出；
- 找回密码、重置密码；
- 登录会话创建、退出撤销、重置密码后的批量撤销；
- 数据库审计记录；
- Portal 单元测试、静态检查和构建；
- 原 Gateway 回归测试。

明确排除：

- 真实 SMTP；
- 真实 3x-ui；
- 链动小铺或任何真实支付；
- 套餐、订单、权益和自动开通；
- 生产环境部署；
- 第二阶段。

## 2. 本地 PostgreSQL 验收环境

使用 `github.com/fergusstrange/embedded-postgres v1.34.0` 在测试进程中启动真实 PostgreSQL：

- PostgreSQL 版本：`17.5`
- 平台：Windows x86-64
- 监听：仅本机 IPv4/IPv6 随机临时端口
- 数据库：测试专用临时数据库
- 数据目录：操作系统测试临时目录
- 生命周期：测试开始时初始化并启动，测试结束快速停止并删除临时数据

最终回归中 PostgreSQL 成功进入“数据库系统准备接受连接”状态，并在测试结束后正常完成 checkpoint 和关闭。验收清理时确认残留 `postgres` 进程数为 `0`。

初始化时 Windows 中文区域设置不能作为 PostgreSQL 服务端编码，`initdb` 自动使用 UTF-8，并将默认文本搜索配置降级为 `simple`。该提示没有导致迁移或测试失败；生产数据库仍需显式确定 locale、collation 和文本搜索策略。

## 3. 数据库迁移验收

集成测试对同一空数据库连续执行两次 `Store.Migrate()`，两次均成功，用于验证初始迁移的幂等性。

随后通过 `to_regclass` 逐表确认以下表实际存在：

- `users`
- `sessions`
- `action_tokens`
- `xui_client_bindings`
- `audit_logs`

本次验收未测试未来多版本迁移、回滚或生产数据升级；当前只能确认初始建表在 PostgreSQL 17.5 空库中可重复执行。

## 4. 认证冒烟流程

集成测试使用实际 Portal HTTP Handler、Cookie Jar、PostgreSQL Store 和 development `LogMailer`，按以下顺序执行：

1. GET 注册页面并取得 CSRF Token。
2. POST 邮箱与密码注册。
3. 从 development 邮件日志中取得一次性邮箱验证 URL。
4. 访问验证 URL，并直接查询数据库确认用户状态为 `active`。
5. 使用原密码登录，确认用户中心显示当前账号。
6. 记录首个会话 Cookie，POST 退出登录。
7. 直接查询 `sessions`，确认首个会话的 `revoked_at` 已写入。
8. 再次使用原密码登录并记录第二个会话。
9. 请求找回密码，从 development 邮件日志取得重置 URL。
10. 使用新密码完成重置。
11. 直接查询 `sessions`，确认第二个会话已由密码重置撤销。
12. 验证原密码登录返回 `401 Unauthorized`。
13. 验证新密码登录成功。

结果：所有步骤通过。

测试没有连接真实邮件服务器。验证和重置链接只由 development 日志邮件适配器生成并在测试进程内解析。

## 6. 验收中发现并修复的问题

### 退出登录缺少审计记录

原实现的 `RevokeSession()` 只更新 `sessions.revoked_at`，没有写入 `audit_logs`，不符合第一阶段安全操作可追踪的要求。

修复后：

- 在单一数据库事务中撤销未撤销的会话；
- 从被撤销会话取得 `user_id`；
- 写入 `auth.logout`、目标用户和 `success` 结果；
- 会话不存在或已经撤销时返回 `ErrNotFound`；
- 事务任一步失败时整体回滚。

修复由真实 PostgreSQL 集成测试验证，最终审计表中 `auth.logout=1`。
