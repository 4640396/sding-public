# 2026-07-17 Vault 导航去重与 Markdown 阅读样式统一验收记录

## 结论

本轮没有继续调整已经稳定的物理目录，而是收口导航职责和 Markdown 展现方式。主页、书架索引、日常维护流程不再重复说明同一套目录与工作流；原有自定义仪表盘布局改为 Obsidian 默认阅读样式，后续笔记按根目录 `AGENTS.md` 中的统一规则维护。

## 已完成内容

### 导航职责去重

- `主页.md` 只保留快速开始、项目入口和常用入口，负责回答“从哪里开始”。
- `书架/书架索引.md` 只说明各目录放什么，负责回答“内容应该放在哪里”。
- `书架/日常维护流程.md` 只保留每日、每周维护清单，负责回答“什么时候做什么”。
- 删除三页之间重复的完整目录规则、项目生命周期和静态“今日”面板；详细治理规则统一以 `AGENTS.md` 为准。

### Markdown 阅读样式统一

- 将 16 份使用 `dashboard-home` 自定义布局的主页、索引、知识地图和插件清单改为普通标题、段落、列表、代码块与 Wiki 链接结构。
- 移除 `cssclasses`、`home-*` 与 `maze-routes` 自定义布局 Callout，以及用于排版的换行、小号文字和行内容器 HTML 标签。
- 为一份缺少一级标题的 Obsidian 插件资料补齐一级标题。
- 删除已经没有引用的 `.obsidian/snippets/dashboard-home.css`。
- 在 `AGENTS.md` 固化统一标准：每篇笔记只使用一个一级标题，按二级、三级标题组织正文；不使用自定义 CSS 类、布局 Callout 或 HTML 搭建页面。
- `note`、`warning`、`important`、`summary` 等标准 Callout 只在确有语义需要时保留，不作为页面布局工具。

## 未验证边界

- 本次没有刷新 Graphify、生成语义图谱或执行 Graphify 关系校验；导航和 Markdown 结构调整不依赖代码或知识关系图。
- 没有逐页生成截图做像素级视觉对比；视觉标准来自用户确认的 GBrain 项目索引阅读效果，验收以结构、布局残留和链接完整性为主。
- 本记录验证的是阅读样式与导航职责，不代表对每份旧笔记的业务内容、来源完整性或历史元数据进行了重新确认。

## 后续维护

- 新建或改造 Markdown 时直接遵循 `AGENTS.md` 的默认阅读样式，不再恢复仪表盘 CSS。
- 页面需要提示风险或结论摘要时，可以使用有明确语义的标准 Callout；不得用 Callout、HTML 或 CSS 类拼装页面布局。
- 主页、书架索引和日常维护流程各守其责；新增规则优先写入唯一规则来源，再由导航页链接过去，避免复制整段规则。
