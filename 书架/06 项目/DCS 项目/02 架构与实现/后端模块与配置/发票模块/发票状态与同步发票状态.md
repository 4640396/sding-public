# 发票状态与同步发票状态

## 三个字段的职责

Global 发票流程同时使用三个状态字段，含义不能混用：

| 字段 | Java 类型/常量 | 表达内容 | 是否代表最终业务结果 |
|---|---|---|---|
| `ic_invoice.invoice_status` | `InvoiceStatus` / `InvoiceStatusConstant` | DCS 发票本体状态 | 是 |
| `ic_invoice.bs_invoice_status` | `BsInvoiceStatus` | BLUE SERV 开票、取消阶段 | 是，仅针对 BS 流程 |
| `ic_invoice.sync_status` | `InvoiceConstant` 字符串常量 | 最近一次 SFTP 请求或回执处理结果 | 否 |

状态值：

```text
invoice_status
0 = CANCELLED
1 = CREATED

bs_invoice_status
null = 尚未收到 BS 开票成功回执
2    = CANCELLING
3    = INVOICED
```

常用 `sync_status`：

```text
-                         默认值
Send Invoice Success      开票请求上传成功
Send Invoice Failed       开票请求上传失败
Get Invoice Success       开票回执处理成功
Send Cancellation Success 取消请求上传成功
Get Cancellation Success  取消回执处理成功
Skipped                   历史或跳过场景
```

## 开票状态矩阵

| 阶段/场景 | `invoice_status` | `bs_invoice_status` | `sync_status` |
|---|---:|---:|---|
| DCS 创建发票 | `1 CREATED` | `null` | `-` |
| 开票请求上传失败 | `1 CREATED` | `null` | `Send Invoice Failed` |
| 请求上传到 `/INVOICE/Pending` | `1 CREATED` | `null` | `Send Invoice Success` |
| BLUE SERV 取走请求并移入 `/INVOICE/Processed` | `1 CREATED` | `null` | `Send Invoice Success` |
| BLUE SERV 正在处理 | `1 CREATED` | `null` | `Send Invoice Success` |
| 回执进入 `/Response_Invoice/Pending`，尚未消费 | `1 CREATED` | `null` | `Send Invoice Success` |
| `SynInvoiceRespJob` 成功处理开票回执 | `1 CREATED` | `3 INVOICED` | `Get Invoice Success` |

BLUE SERV 把请求移动到 `/INVOICE/Processed` 不会更新 DCS 数据库。只有 `SynInvoiceRespJob` 消费 `Response_...` 回执后，`bs_invoice_status` 才会成为 `INVOICED(3)`。

## Cancel 判断矩阵

是否走 BS 取消不能只根据“开票请求已上传到 SFTP”判断，当前代码结合 `bs_invoice_status` 和开票请求文件是否仍在 Pending 判断：

| 当前状态 | 请求文件状态 | Cancel 结果 |
|---|---|---|
| `invoice_status=CREATED`、`bs_invoice_status!=INVOICED` | 请求仍在 `/INVOICE/Pending` | 删除 Pending 请求，执行内部取消，不向 BS 发送取消请求 |
| `invoice_status=CREATED`、`bs_invoice_status!=INVOICED` | 请求已被 BS 取走，不在 Pending | 阻止取消，提示 `The BS is already in processing and cannot be cancelled` |
| `bs_invoice_status=INVOICED(3)` | 开票回执已由 DCS 消费 | 上传 `Can_*.xls`，进入外部取消，等待 BS 回执 |

开票请求仍在 `/DCS/SMMX/INVOICE/Pending/` 时直接取消符合当前设计，与 `SynInvoiceRespJob` 是否开启无关。只有 BS 已生成开票回执而 DCS 未写入 `bs_invoice_status=INVOICED` 时，才需要排查回执 Job。

## 内部取消的实际落库行为

内部取消适用于尚未同步的发票，或开票请求仍在 `/INVOICE/Pending` 的发票。

处理过程：

1. 如 Pending 中存在开票请求文件，先删除文件。
2. 执行 DCS 领域取消、事件发布和关联流程清理。
3. 最后通过回调删除 `ic_invoice` 中的发票记录。

因此，内部取消最终不是保留以下状态：

```text
invoice_status=0
bs_invoice_status=null
```

而是：

```text
ic_invoice 记录被删除，三个状态字段不再可查询。
```

这是对 2026-07-16 早期排查结论的修正，以当前 `InvoiceCancelStrategyContext` 中 `supplier.get()` 的实际行为为准。

## 外部取消状态矩阵

外部取消的前提是 `bs_invoice_status=INVOICED(3)`。

| 阶段/场景                        | `invoice_status` | `bs_invoice_status` | `sync_status`               |
| ---------------------------- | ---------------: | ------------------: | --------------------------- |
| BS 已开票                       |      `1 CREATED` |        `3 INVOICED` | `Get Invoice Success`       |
| 取消请求上传成功                     |      `1 CREATED` |      `2 CANCELLING` | `Send Cancellation Success` |
| BLUE SERV 取走取消请求             |      `1 CREATED` |      `2 CANCELLING` | `Send Cancellation Success` |
| 取消回执进入 Response Pending      |      `1 CREATED` |      `2 CANCELLING` | `Send Cancellation Success` |
| `SynInvoiceRespJob` 成功处理取消回执 |    `0 CANCELLED` |      `2 CANCELLING` | `Get Cancellation Success`  |
|                              |                  |                     |                             |

取消回执处理过程：

1. 校验 `sync_status=Send Cancellation Success`。
2. 条件更新要求 `bs_invoice_status=CANCELLING(2)`。
3. 写入取消日期和 `sync_status=Get Cancellation Success`。
4. 调用 `doCancelAndReversedInvoice(..., true)` 完成领域取消。
5. `invoice_status` 最终写为 `CANCELLED(0)`。

当前代码没有清空或改写 `bs_invoice_status`，领域仓储使用 selective update，因此最终仍保留 `CANCELLING(2)`。

## 异常状态

| 异常场景 | 当前实际状态/行为 |
|---|---|
| 开票请求上传失败 | 写入 `Send Invoice Failed` |
| 开票回执解析或更新失败 | 保持 `Send Invoice Success`，响应文件留在 Pending，记录 Job 日志 |
| 取消请求上传失败 | 外层事务回滚，通常恢复为 `bs_invoice_status=3`、`sync_status=Get Invoice Success` |
| 取消回执解析或处理失败 | 保持 `bs_invoice_status=2`、`sync_status=Send Cancellation Success`，响应文件留在 Pending |

代码虽然定义了以下失败常量，但当前没有实际写入路径：

```text
Get Invoice Failed
Send Cancellation Failed
get Cancellation Failed
```

## 当前待业务确认项

BS 取消回执成功后，当前落库为：

```text
invoice_status    = 0  (CANCELLED)
bs_invoice_status = 2  (CANCELLING)
sync_status       = Get Cancellation Success
```

`invoice_status=0` 已明确表达发票本体取消成功，但 `bs_invoice_status=CANCELLING` 的最终语义不完整。需要业务确认以下方案：

- 取消回执成功后清空 `bs_invoice_status`；
- 或为 `BsInvoiceStatus` 增加最终 `CANCELLED` 状态。

确认前该项属于待确认设计点，不应表述为已解决。

## SMMX 回执 Job 迁移差异

`SynInvoiceRespJob` 迁移到 Global 时保留了 SMMX 的目录扫描、文件锁、Excel 解析、开票/取消分支、事务和归档流程。Global 必须适配：

- 使用 `InvoiceBsFileSftpServer`。
- 操作人使用 `global_veh_admin`。
- 开票回执写 `bsInvoiceStatus=INVOICED`，不能把 `3` 写入 `invoiceStatus`。
- 取消回执的条件更新使用 `bsInvoiceStatus=CANCELLING`。
