# MX OEM STOCK 单车 POC 结论与证据

## 已确认

- 原始模板订单 Sheet 为 A:O、包含 `VIN`；业务确认实际使用 `ZA采购发运期初数据1.xlsx`，其订单 Sheet 为 A:N、不含 VIN。
- `PurchaseAndShippingVo` 明确映射“订单”Sheet 的 `VIN`。
- 但 `PurchaseAndShippingVo.toOrder()` 和 `toOrderItem()` 均不使用 VIN，因此删除该列不会影响订单对象字段生成。
- 无 VIN 订单 Sheet 仍保留“开票日期”，导出 SQL 按 A:N 顺序输出。
- `initGdsShippingData` 按订单号、物料分组，以订单 Sheet 同组行数设置 `OrderItemVo.qty`；因此可以删列，但不能合并同物料的车辆行。
- “发运”Sheet由 `SmmeDeliveryItemVo` 读取，一辆车一行，并按销售订单号挂到采购订单。
- `tom_trade_order.data_status=4` 的表定义含义是 Approved；目前没有证据表明墨西哥与全球在这个值上存在枚举差异。
- 当前生产查询环境不接受 CTE，因此交付 SQL 使用 MySQL 5.7 兼容的普通 JOIN 和相关子查询。

## 风险与未验证项

- Gate In 历史记录表通过 `inventory_vehicle_no` 与 `warehouse_inventory_vehicle` 关联；业务日期取 `gate_in_date`。此前使用不存在的 `warehouse_inventory_vehicle_no` 已修正。

- 最新 GDS 记录中的 `send_time`、`submit_date`、`bl_date` 可能为空；当前转换代码会直接解析对应字符串，空值会导致转换失败。
- 不允许为了通过转换而在生产取数 SQL 中伪造日期。若所有候选均缺日期，应单独决策是否在 UAT 修改转换逻辑。
- SQL 尚未在生产只读平台完整执行；字段差异和性能仍需以实际执行结果为准。
- Gate In 历史日期应与业务库存清单核对，不能仅凭某张历史迁移快照认定为最新事实。

## 被替代结论

“删除 VIN 后可以把每个订单物料合并为一行”不成立。正确规则是：VIN 列可以删除，但仍须按车辆保留重复的订单物料行，接口再以行数汇总 `qty`。
