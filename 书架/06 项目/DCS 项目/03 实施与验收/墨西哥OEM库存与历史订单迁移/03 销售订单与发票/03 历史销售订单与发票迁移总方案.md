# MX历史销售订单与发票迁移总方案

> [!important] 目标
> 将墨西哥生产库中已经真实销售给 Dealer 的历史车辆，按原始事实恢复到全球库的最终已售状态。顺序必须是：上游采购与发运 → 历史 Gate In → Seller 销售与物流 → Seller 发票。当前仍为 `OEM_STOCK` 的车辆不进入本方案。

业务方向：先恢复“墨西哥向总部采购”的上游事实；车辆进入墨西哥后，再恢复“Dealer向墨西哥采购”的Seller销售事实。

> [!warning] 同一OEM订单只能创建一次
> 在阶段01期初库存或本阶段首次调用采购`save`前，必须建立跨阶段OEM订单台账。若同一OEM订单同时包含阶段01已确认库存VIN和本阶段已确认历史销售VIN，必须把两个业务范围内的VIN合并到该订单首次上游导入中；后续不得使用相同订单号补VIN。合并范围不包含未进入任一业务确认清单的其他VIN。

## 一、全量导出与批次入口

1. 运维分别执行 [[01 Seller模板生产只读取数#1、导出 Order Sheet|1号 Order SQL]]、[[01 Seller模板生产只读取数#2、导出 Invoice Sheet|2号 Invoice SQL]]、[[01 Seller模板生产只读取数#3、导出 Logistics Sheet|3号 Logistics SQL]]，交付三个完整 Excel。
2. 本地确认三个文件各自 `(Order No, VIN)` 不重复，且三者集合完全一致。
3. 将Seller VIN对应的上游OEM订单号与阶段01台账做交叉检查；共享OEM订单必须在首次采购保存时合并处理。
4. 验收通过后再按 Seller 订单拆批；首批只选 1 个完整 Seller 订单，记录：

```text
<BATCH_SELLER_ORDER_NO_LIST>
Seller订单数
VIN数
Dealer数
Seller发票数
upstream_oem_order_nos
```

后续旧批次排查 SQL 的参数格式：

```text
'SELLER_ORDER_A','SELLER_ORDER_B'
```

运维全量导出的 1、2、3 号 SQL 没有占位符，不得追加时间条件。只有进入后续旧批次排查时才替换尖括号参数；执行前搜索字符 `<` 的结果必须为 0。

## 二、上游链路完整性预检

一辆 Seller VIN 必须唯一追溯到一个 `5000 → 270165` 的已审批 OEM 采购订单和一种有效成功GDS业务指纹。同一业务指纹存在多条成功同步记录时，后续导出才按`im_time DESC, id DESC`选择最新同步行。

```sql
SELECT
    seller_order.trade_order_no AS seller_order_no,
    seller_vo.vin,
    COUNT(DISTINCT oem_order.trade_order_no) AS upstream_oem_order_count,
    GROUP_CONCAT(DISTINCT oem_order.trade_order_no
        ORDER BY oem_order.trade_order_no SEPARATOR ',') AS upstream_oem_order_nos,
    COUNT(DISTINCT g.id) AS successful_gds_sync_count,
    COUNT(DISTINCT CASE WHEN g.id IS NOT NULL THEN CONCAT_WS('|',
        gi.customer_order_no,
        IFNULL(g.invoice_no, ''),
        IFNULL(gi.delivery_no, ''),
        IFNULL(gi.sap_out_delivery_no, ''),
        IFNULL(g.ship_to_party_no, ''),
        IFNULL(g.port_of_destination, ''),
        IFNULL(DATE_FORMAT(g.etd, '%Y-%m-%d'), ''),
        IFNULL(DATE_FORMAT(g.invoice_date, '%Y-%m-%d'), '')
    ) END) AS successful_gds_fingerprint_count,
    COUNT(DISTINCT wivg.id) AS gate_in_record_count,
    COUNT(DISTINCT wivgo.id) AS gate_out_record_count,
    CASE
      WHEN COUNT(DISTINCT oem_order.trade_order_no) <> 1
        THEN 'STOP:OEM_ORDER_COUNT'
      WHEN COUNT(DISTINCT g.id) = 0
        THEN 'STOP:GDS_NOT_FOUND'
      WHEN COUNT(DISTINCT CASE WHEN g.id IS NOT NULL THEN CONCAT_WS('|',
          gi.customer_order_no,
          IFNULL(g.invoice_no, ''),
          IFNULL(gi.delivery_no, ''),
          IFNULL(gi.sap_out_delivery_no, ''),
          IFNULL(g.ship_to_party_no, ''),
          IFNULL(g.port_of_destination, ''),
          IFNULL(DATE_FORMAT(g.etd, '%Y-%m-%d'), ''),
          IFNULL(DATE_FORMAT(g.invoice_date, '%Y-%m-%d'), '')
      ) END) <> 1
        THEN 'STOP:GDS_FINGERPRINT_COUNT'
      WHEN COUNT(DISTINCT wivg.id) <> 1
        THEN 'STOP:GATE_IN_COUNT'
      WHEN COUNT(DISTINCT wivgo.id) <> 1
        THEN 'STOP:GATE_OUT_COUNT'
      ELSE 'PASS'
    END AS scope_check
FROM tom_trade_order seller_order
JOIN tom_vehicle_order seller_vo
  ON seller_vo.trade_order_no = seller_order.trade_order_no
JOIN tom_vehicle_order oem_vo
  ON oem_vo.vin = seller_vo.vin
JOIN tom_trade_order oem_order
  ON oem_order.trade_order_no = oem_vo.trade_order_no
 AND oem_order.sales_company_no = '5000'
 AND oem_order.customer_no = '270165'
 AND oem_order.data_status = 4
LEFT JOIN lm_gds_delivery_interface_item gi
  ON gi.vehicle_vin = seller_vo.vin
 AND gi.customer_order_no = oem_order.trade_order_no
LEFT JOIN lm_gds_delivery_interface g
  ON g.id = gi.lm_delivery_interface_id
 AND g.e_type = 'S'
 AND g.ship_to_party_no = '270165'
LEFT JOIN warehouse_inventory_vehicle wiv
  ON wiv.vin = seller_vo.vin
LEFT JOIN warehouse_inventory_vehicle_gated_in_note wivg
  ON wivg.inventory_vehicle_no = wiv.inventory_vehicle_no
LEFT JOIN warehouse_inventory_vehicle_gated_out_note wivgo
  ON wivgo.inventory_vehicle_no = wiv.inventory_vehicle_no
WHERE seller_order.trade_order_no IN (<BATCH_SELLER_ORDER_NO_LIST>)
GROUP BY seller_order.trade_order_no, seller_vo.vin
ORDER BY seller_order.trade_order_no, seller_vo.vin;
```

任一 VIN 不是 `PASS`，停止整批。

## 三、导出上游采购订单Sheet

一辆 Seller VIN 一行，结果粘贴到采购发运模板“订单”Sheet。

```sql
SELECT
    oem_order.trade_order_no                       AS `客户订单号`,
    DATE_FORMAT(oem_order.pricing_date, '%Y-%m-%d') AS `销售定价日期`,
    DATE_FORMAT(oem_order.pricing_date, '%Y-%m-%d') AS `下单日期`,
    '270165'                                       AS `DEALER SAP NO`,
    oem_order.delivery_destination                 AS `DELIVERY SHORT NAME`,
    tm.vehicle_material_code                       AS `Material Code`,
    g.invoice_no                                   AS `INVOICE NO`,
    oem_order.incoterm_code                        AS `Incoterm`,
    tm.unit_price                                  AS `Price`,
    oem_order.currency                             AS `Currency`,
    tm.material_description                        AS `Material Description`,
    tm.interior_description                        AS `Interior Description`,
    tm.exterior_description                        AS `Exterior Description`
FROM tom_trade_order seller_order
JOIN tom_vehicle_order seller_vo
  ON seller_vo.trade_order_no = seller_order.trade_order_no
JOIN tom_vehicle_order oem_vo
  ON oem_vo.vin = seller_vo.vin
JOIN tom_trade_order oem_order
  ON oem_order.trade_order_no = oem_vo.trade_order_no
 AND oem_order.sales_company_no = '5000'
 AND oem_order.customer_no = '270165'
JOIN tom_trade_order_material tm
  ON tm.trade_order_no = oem_order.trade_order_no
 AND tm.vehicle_material_code = oem_vo.vehicle_material_code
JOIN lm_gds_delivery_interface_item gi
  ON gi.vehicle_vin = seller_vo.vin
 AND gi.customer_order_no = oem_order.trade_order_no
JOIN lm_gds_delivery_interface g
  ON g.id = gi.lm_delivery_interface_id
 AND g.e_type = 'S'
 AND g.ship_to_party_no = '270165'
 AND g.id = (
      SELECT g2.id
      FROM lm_gds_delivery_interface_item gi2
      JOIN lm_gds_delivery_interface g2
        ON g2.id = gi2.lm_delivery_interface_id
      WHERE gi2.vehicle_vin = seller_vo.vin
        AND gi2.customer_order_no = oem_order.trade_order_no
        AND g2.e_type = 'S'
        AND g2.ship_to_party_no = '270165'
      ORDER BY g2.im_time DESC, g2.id DESC
      LIMIT 1
 )
WHERE seller_order.trade_order_no IN (<BATCH_SELLER_ORDER_NO_LIST>)
ORDER BY oem_order.trade_order_no, seller_vo.vin;
```

## 五、导出历史Gate In

```sql
SELECT
    seller_vo.vin                                  AS `VIN`,
    CAST(wivg.quality AS CHAR)                     AS `Quality`,
    DATE_FORMAT(wivg.gate_in_date, '%Y-%m-%d')    AS `Gate In Date`,
    COALESCE(wivg.customs_release_no, '')          AS `Customs Release #（optional）`,
    ''                                             AS `photo`,
    CONCAT('MX SOLD HISTORY ', seller_order.trade_order_no) AS `Notes`,
    wiv.warehouse_no                               AS `Warehouse Check`
FROM tom_trade_order seller_order
JOIN tom_vehicle_order seller_vo
  ON seller_vo.trade_order_no = seller_order.trade_order_no
JOIN warehouse_inventory_vehicle wiv
  ON wiv.vin = seller_vo.vin
JOIN warehouse_inventory_vehicle_gated_in_note wivg
  ON wivg.inventory_vehicle_no = wiv.inventory_vehicle_no
WHERE seller_order.trade_order_no IN (<BATCH_SELLER_ORDER_NO_LIST>)
ORDER BY seller_order.trade_order_no, seller_vo.vin;
```

`Warehouse Check` 仅用于选择 UAT Gate In 目标仓，不粘贴到 Gate In 模板。每个 VIN 必须只有一条有效历史 Gate In；重复时停止。

## 六、恢复上游采购、发运和Gate In

1. 采购模板只保留当前批次数据。
   若上游OEM订单已在阶段01创建，禁止再次调用采购`save`；该订单所需的历史销售VIN必须已经包含在首次上游导入中，否则停止并重新制定补数方案。
2. 调用 `/ops/smza-order/initGdsShippingData`，`salesCompanyNo=5000`。
3. 检查 JSON：`customerNo=270165`，订单、qty、VIN、采购发票与生产一致。
4. 调用 `/ops/smpOrder/save`。
5. 按历史仓库和 Gate In Date 执行 Gate In。
6. 验收所有 VIN 已在正确仓库，且暂无 Seller 销售关系。

任一步失败，停止，不进入 Seller 阶段。

## 七、生成并导入Seller销售订单

1. 按 [[01 Seller模板生产只读取数]] 的1号、2号、3号 SQL生成 `Order`、`Invoice`、`Logistics` Sheet。
2. Seller源导出中的历史 `E000` 映射为目标环境 `L000`；Dealer、目的地、售价、日期和发票号保持真实值。
3. 按 [[02 Seller批量执行方案]] 调用 `/ops/smza-order/initData`。
4. 检查 `smzaSalesOrder.json` 后调用 `/ops/smza-order/save`。

销售保存成功条件：

```text
successList数量 = Seller订单数
duplicateIgnored为空
failed为空
每个VIN已分配到Seller订单
DN、Gate Out、Received日期与生产一致
车辆订单data_status = 7（Matched）
```

## 八、生成并导入Seller发票

1. 调用 `/ops/smza-order/initInvoiceInfo`。
2. 从固定位置 `E:\initdata\Order\invoice.json` 立即复制为批次文件。
3. 核对订单、VIN、发票号和日期。
4. 调用 `/ops/order/invoice`。

成功条件：

```text
successList数量 = Invoice JSON行数
duplicateIgnored为空
failed为空
每个Order No + VIN只有一条有效Seller发票
```

## 九、端到端验收

```text
每个Seller VIN唯一追溯到上游OEM采购订单
采购发运、历史Gate In、Seller DN链路完整
Dealer、目的地、物料、销售价格和币种正确
Gate Out、Received与生产真实日期一致
Seller发票号和日期正确
车辆最终不是OEM可用库存，而是历史已售状态
```

## 十、批次策略

- 先执行1个完整 Seller 订单。
- 单单端到端通过后扩到5个完整 Seller订单。
- 连续两批通过后扩到20个，不拆订单或发票闭包。
- 每批保存生产 SQL 结果、两个 Excel、采购 JSON、Seller JSON、Invoice JSON、接口完整响应和批后验收证据。

## 十一、立即停止条件

- VIN 出现在当前切换日 `OEM_STOCK` 清单中，但生产 Seller 历史与库存状态冲突。
- 上游 OEM 订单、最新 GDS、历史 Gate In 或 Gate Out 不能唯一确定。
- UAT 缺少 Dealer、目的地或仓库主数据。
- 任一真实业务日期为空。
- 任何阶段出现重复、超时、`failed` 或 `duplicateIgnored`。
- Excel、JSON、数据库的订单、VIN、qty、发票集合不一致。
- 为通过转换器而伪造 Dealer、价格、日期或发票号。

## 十二、验证与生产边界

本方案为 `accepted`，源码和静态表结构已核对，但历史销售端到端尚未完成 UAT 单单验证。只有单单、扩批、失败恢复和目标生产主数据复核全部通过，并取得独立生产变更授权后，才能进入生产执行准备；本方案本身不授权生产写入。
