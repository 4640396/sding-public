# 墨西哥未发运OEM采购订单迁移执行方案

> [!important] 只执行本页
> 本方案只处理生产中已审批、整单尚未分配VIN、整单没有成功GDS的OEM采购订单。只恢复采购订单和空VIN车辆订单，不创建Shipping、DN/ASN、待入库或库存，不执行Gate In、Seller销售单或发票。0A、0B及旧SQL已移入[[../99 历史草案/未发运订单SQL排查记录]]，不再执行。

业务关系只有一条：**总部（5000，卖方）→ 墨西哥（买方）**。本页不是“墨西哥→经销商”的Seller销售订单方案。

## 零、执行速查

需要执行**两个SQL**，顺序和交付物如下：

| 顺序 | 执行内容 | 导出文件 | 文件用途 |
|---|---|---|---|
| 1 | 本页“二、SQL-1：全量导入明细” | `01_Unshipped_Purchase_Order_Full.xlsx` | 制作采购订单导入模板；一行对应一辆空VIN车辆订单 |
| 2 | 本页“三、SQL-2：全量验收汇总” | `02_Unshipped_Purchase_Order_Check.xlsx` | 核对每个“订单+物料”的qty、车辆订单数和VIN |

两个文件缺一不可。执行时不要增加时间、订单号或物料条件，也不要只导出页面显示的部分数据。

收到两个Excel后，先完成第四章的数量闭包；全部通过后，才从SQL-1文件中提取一个完整订单做UAT单单验证。

## 一、执行边界

必须同时满足：

```text
生产卖方 = 5000
生产买方 = 270165
目标UAT买方 = 270165
订单来源 = 1
订单状态 = 4（Approved）
订单全部物料均迁移，不固定物料
每个物料的车辆订单数 = 物料qty
整单所有车辆VIN为空
整单不存在e_type='S'成功GDS
```

存在任意VIN、任意成功GDS、部分发运或数量不一致的订单均不进入本方案。

## 二、SQL-1：全量导入明细

先执行本SQL。运维在获批的生产只读客户端完整导出全部结果，不增加订单号、物料或时间条件。

```sql
SELECT
    tor.trade_order_no                         AS `客户订单号`,
    DATE_FORMAT(tor.pricing_date, '%Y-%m-%d') AS `销售定价日期`,
    DATE_FORMAT(tor.pricing_date, '%Y-%m-%d') AS `下单日期`,
    '270165'                                   AS `DEALER SAP NO`,
    tor.delivery_destination                   AS `DELIVERY SHORT NAME`,
    tm.vehicle_material_code                   AS `Material Code`,
    NULL                                       AS `INVOICE NO`,
    tor.incoterm_code                          AS `Incoterm`,
    tm.unit_price                              AS `Price`,
    tor.currency                               AS `Currency`,
    tm.material_description                    AS `Material Description`,
    tm.interior_description                    AS `Interior Description`,
    tm.exterior_description                    AS `Exterior Description`
FROM tom_trade_order tor
JOIN tom_trade_order_material tm
  ON tm.trade_order_no = tor.trade_order_no
JOIN tom_vehicle_order vo
  ON vo.trade_order_no = tor.trade_order_no
 AND vo.vehicle_material_code = tm.vehicle_material_code
JOIN md_organization buyer_org
  ON buyer_org.customer_no = tor.customer_no
 AND buyer_org.sales_company_no = 'L000'
 AND buyer_org.uuid = tor.buyer_uuid
WHERE tor.sales_company_no = '5000'
  AND tor.customer_no = '270165'
  AND tor.source_code = 1
  AND tor.data_status = 4
  AND (vo.vin IS NULL OR vo.vin = '')
  AND tm.qty = (
      SELECT COUNT(DISTINCT vo_qty.vehicle_order_no)
      FROM tom_vehicle_order vo_qty
      WHERE vo_qty.trade_order_no = tor.trade_order_no
        AND vo_qty.vehicle_material_code = tm.vehicle_material_code
  )
  AND NOT EXISTS (
      SELECT 1
      FROM tom_vehicle_order vo_vin
      WHERE vo_vin.trade_order_no = tor.trade_order_no
        AND vo_vin.vin IS NOT NULL
        AND vo_vin.vin <> ''
  )
  AND NOT EXISTS (
      SELECT 1
      FROM lm_gds_delivery_interface_item gi
      JOIN lm_gds_delivery_interface g
        ON g.id = gi.lm_delivery_interface_id
       AND g.e_type = 'S'
      WHERE gi.customer_order_no = tor.trade_order_no
  )
ORDER BY tor.trade_order_no, tm.vehicle_material_code, vo.vehicle_order_no;
```

本SQL只导出一个文件：

```text
01_Unshipped_Purchase_Order_Full.xlsx
```

该文件是后续制作导入模板的数据源，不是验收汇总文件。

> [!warning] SQL审计平台限制
> 若审计平台报`Required keyword: 'this' missing`，属于平台对`EXISTS/NOT EXISTS`的解析限制，不是MySQL语法错误。运维应改用获批的原生生产只读客户端，不能删除两个`NOT EXISTS`条件。

## 三、SQL-2：全量验收汇总

SQL-1完整导出后，再执行本SQL，并导出：

```text
02_Unshipped_Purchase_Order_Check.xlsx
```

该文件不能用于导入。一行代表一个“订单+物料”，用于独立核对期望qty、实际车辆订单数和VIN；成功GDS订单已由查询条件整单排除。

```sql
SELECT
    tor.trade_order_no AS `客户订单号`,
    tm.vehicle_material_code AS `Material Code`,
    tm.qty AS `Expected Qty`,
    COUNT(DISTINCT vo.vehicle_order_no) AS `Vehicle Order Count`,
    COUNT(DISTINCT NULLIF(TRIM(vo.vin), '')) AS `Allocated VIN Count`,
    CASE
      WHEN tm.qty = COUNT(DISTINCT vo.vehicle_order_no)
       AND COUNT(DISTINCT NULLIF(TRIM(vo.vin), '')) = 0
      THEN 'PASS'
      ELSE 'STOP'
    END AS `Qty And VIN Check`
FROM tom_trade_order tor
JOIN tom_trade_order_material tm
  ON tm.trade_order_no = tor.trade_order_no
JOIN tom_vehicle_order vo
  ON vo.trade_order_no = tor.trade_order_no
 AND vo.vehicle_material_code = tm.vehicle_material_code
JOIN md_organization buyer_org
  ON buyer_org.customer_no = tor.customer_no
 AND buyer_org.sales_company_no = 'L000'
 AND buyer_org.uuid = tor.buyer_uuid
WHERE tor.sales_company_no = '5000'
  AND tor.customer_no = '270165'
  AND tor.source_code = 1
  AND tor.data_status = 4
  AND NOT EXISTS (
      SELECT 1
      FROM tom_vehicle_order vo_vin
      WHERE vo_vin.trade_order_no = tor.trade_order_no
        AND vo_vin.vin IS NOT NULL
        AND vo_vin.vin <> ''
  )
  AND NOT EXISTS (
      SELECT 1
      FROM lm_gds_delivery_interface_item gi
      JOIN lm_gds_delivery_interface g
        ON g.id = gi.lm_delivery_interface_id
       AND g.e_type = 'S'
      WHERE gi.customer_order_no = tor.trade_order_no
  )
GROUP BY tor.trade_order_no, tm.vehicle_material_code, tm.qty
ORDER BY tor.trade_order_no, tm.vehicle_material_code;
```

验收SQL的每一行必须同时满足：

```text
Expected Qty = Vehicle Order Count
Allocated VIN Count = 0
Qty And VIN Check = PASS
```

## 四、收到Excel后的验收

未通过以下检查不得制作导入文件：

```text
完整导出，不受页面最大显示行数截断
VIN全部为空
INVOICE NO全部为空
DEALER SAP NO全部为270165
客户订单号、物料、价格、币种、Incoterm和日期均有生产值
每个订单必须保留全部物料
每个“订单+物料”的Excel行数 = 对应物料qty
```

从Excel随机抽取至少3个订单回查生产：确认整单无VIN、整单无成功GDS。任意抽样失败，整份Excel停止使用，不手工删行掩盖问题。

### Excel具体核对方法

1. 打开`01_Unshipped_Purchase_Order_Full.xlsx`，新增辅助列`Key`：

```excel
=[@[客户订单号]]&"|"&[@[Material Code]]
```

2. 新建数据透视表：行放`客户订单号`、`Material Code`，值放`Material Code`并设置为“计数”。该计数就是模板明细行数。
3. 打开`02_Unshipped_Purchase_Order_Check.xlsx`，新增同样的`Key`。
4. 在明细透视结果旁使用`XLOOKUP`按Key读取验收文件的`Expected Qty`；旧版Excel可使用`VLOOKUP`或“合并查询”。
5. 比较“明细行计数”和`Expected Qty`，必须全部相等。
6. 在验收文件筛选：`Allocated VIN Count<>0`或`Qty And VIN Check<>PASS`，筛选结果必须为0行。
7. 分别统计两个文件的Key去重数，必须一致；任意一边多出Key都停止。

如果不方便使用数据透视表，可以把两个Excel交给Codex做离线核对；核对只读取文件，不连接或修改生产数据库。

## 五、当前验证结论与首单选择

截至2026-07-19，修订后的验收SQL已经返回满足以下条件的候选订单：

```text
Expected Qty = Vehicle Order Count
Allocated VIN Count = 0
Qty And VIN Check = PASS
买方customer_no、sales_company_no=L000及buyer_uuid一致
整单不存在成功GDS
```

已看到的候选包括`MXASMIL2504150001`、`MXASMIL2510290002`和`MXASMIL2607030001`。其中`MXASMIL2504150001`可见8个物料、合计qty为437，可优先作为UAT单单候选。

`MXASMIL25021740001`已因`BUYER_UUID_MISMATCH`排除，不得迁移。详细排查证据见[[../99 历史草案/未发运订单SQL排查记录]]。

> [!note] 页面查询是辅助一致性检查
> `Order Inquiry by VIN`不能代替生产SQL判断订单是否未发运，也不能仅凭页面没有VIN作结论。页面查不到时先核对组织UUID、接口过滤条件和页面数据域；原因未解释前暂停该订单。最终准入以本页正式SQL、验收SQL、组织一致性及页面差异已解释为准。

## 六、制作首个单单模板

1. 从验收通过的Excel中选择一个数量最小的完整订单。
2. 复制已确认用于`initGdsShippingData`的采购发运模板，不覆盖源模板。
3. 清除全部参考数据。
4. 将该订单的全部物料和全部数据行粘贴到“订单”Sheet。
5. “发运”Sheet只保留表头，数据行必须为0。
6. 不填写VIN、发票号或物流日期，不拆订单或物料。

## 七、Excel转JSON

```text
POST /ops/smza-order/initGdsShippingData
file=<单单测试Excel>
path=<UAT应用服务器可写目录，末尾保留路径分隔符>
salesCompanyNo=5000
```

生成`PurchaseAndShipping.json`后检查：

```text
顶层订单数 = 1
salesCompanyNo = 5000
customerNo = 270165
每个items[].qty = Excel对应订单物料行数
deliveryItemVos = []
JSON不存在VIN、发票号和物流日期
```

空发运Sheet的转换行为尚未UAT实测。接口报空指针、JSON未生成或`deliveryItemVos`不为空时立即停止，不得手工拼JSON继续。

## 八、UAT单单导入

导入前确认UAT不存在同号采购订单、车辆订单、GDS、DN/ASN。然后调用：

```text
POST /ops/smpOrder/save
Content-Type: application/json
Body=<PurchaseAndShipping.json完整数组>
```

接口成功标准：

```text
外层success = true
successList仅包含目标订单
duplicateIgnored为空
failed为空
```

## 九、单单批后验收

```text
采购订单数 = 1
全部订单物料和qty正确
车辆订单数 = 订单总qty
全部车辆订单VIN为空
GDS发运记录数 = 0
DN/ASN数 = 0
待入库记录数 = 0
库存记录数 = 0
```

通过后只能标记“未发运采购订单单单导入成功”，不能标记期初库存或Gate In成功。

## 十、后续GDS链路验收

用该迁移订单执行一次获批的模拟或真实后续GDS发运，验证能够针对已迁移采购订单正常创建VIN、发运和待入库数据。该链路未通过前不得全量导入未发运订单，也不得再次调用`/ops/smpOrder/save`补发运。

## 十一、扩批策略

1. 单单的转换、保存、数据库验收和后续GDS链路全部通过。
2. 扩到5个完整订单。
3. 连续两批通过后扩到20个完整订单。
4. 每批独立保存Excel、JSON、接口完整响应和批后数据库验收证据。
5. 当前批完全收口后才开始下一批。

## 十二、立即停止条件

- 运维修改正式SQL条件或只导出页面显示行数。
- Excel出现VIN、发票、物流日期或部分订单物料。
- 空发运Sheet无法转换，或`deliveryItemVos`不是空数组。
- UAT已存在同订单或前次部分导入数据。
- 接口超时，或`failed`、`duplicateIgnored`非空。
- 批后出现GDS、DN/ASN、待入库或库存。
- 后续GDS无法承接已迁移采购订单。
- 订单`customer_no`正确但`buyer_uuid`与该客户对应的墨西哥组织UUID不一致。
- 页面与生产SQL结果不一致且原因尚未解释。
