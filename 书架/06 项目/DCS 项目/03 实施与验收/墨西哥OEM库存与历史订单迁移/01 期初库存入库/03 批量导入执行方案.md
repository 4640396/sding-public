# MX OEM STOCK 按业务 VIN 批量导入执行方案

> [!important] 2026-07-22 UAT 当前参数纠正
> 用户确认 UAT 当前已使用客户号 `270165`。现行 UAT 与 PRD 的订单客户编号、发运 Customer Number 和 Ship-to Party Number 均使用 `270165`；此前 `220202` 仅保留为 2026-07-18 单车 POC 的历史环境证据，不再用于当前批量执行。任何文件名或目录名包含 `UAT_220202` 的旧模板都不得继续执行，必须改用或重新生成 `270165` 版本并重新校验。

> [!important] 已确认业务口径
> 业务库存 VIN 是唯一白名单。一个业务库存 VIN 只恢复一个有效 OEM 采购订单、一条形成当前库存的有效发运记录和一次 Gate In。同订单、同发票下的其他非业务 VIN 直接忽略，不进入模板和 DCS。

业务方向：**墨西哥向总部采购**。总部`5000`是卖方，墨西哥是买方；随后由总部GDS发运，车辆在墨西哥Gate In后形成OEM库存。

> [!warning] 跨阶段OEM订单闭包
> 执行本阶段采购`save`前，必须先与“03 销售订单与发票”的已确认历史销售VIN做OEM订单号交叉检查。同一OEM订单若同时包含阶段01库存VIN和阶段03历史销售VIN，必须在首次采购保存时合并本次两个业务范围内的VIN并一次性创建订单；不得先创建库存子集、后续再用相同订单号补历史销售VIN。未进入任一业务确认范围的其他VIN仍不迁移。

## 一、冻结业务输入

来源文件：`$env:WORKS_ROOT\initdata\Order\Initial Stock Preparation - July 15 2026.xlsx`，使用 `WarehouseStockDetailVpo` Sheet 第 7 行以下、`PROCESSSTATUS=OEM_STOCK` 的记录。

正式执行前固化：文件名、文件哈希、业务确认人、确认时间和切换日期。VIN 必须非空且唯一。当前文件快照核对为 18,449 个唯一 VIN、8 个仓库、Gate In 日期无空值；正式执行仍需重算并取得业务确认。

## 二、执行边界

```text
一个业务库存 VIN
→ 一个有效 OEM 采购订单
→ 一条形成当前库存的有效发运记录
→ 一次 Gate In
```

- 订单有效条件：`5000 → 270165`、`source_code=1`、`data_status=4`、`shipper=1`。
- 发运有效条件：属于该 VIN 和 OEM 订单、`e_type='S'`、必要字段完整。
- 多条成功同步记录只有业务指纹完全相同时才按最新同步行去重。
- 同订单、同发票下不在业务白名单中的 VIN 不导入、不 Gate In，也不作为当前批次阻断项。
- 一个 VIN 命中多个有效 OEM 订单，或者存在多种有效发运业务指纹时停止该 VIN。

## 三、范围发现和归批

当前批次准备结果见 [[04 生产数据比对与批次模板准备记录]]。2026-07-21 本地核对已确认：18,449 个业务唯一 VIN 全部命中新版运维导出；18,396 辆进入 86 个完整 OEM 订单、13 个常规批次；53 辆模板字段异常单独隔离；261,828 个非业务候选 VIN 已排除。特殊 Ship-to 的 20 辆经订单买方校验后恢复，并已包含在 18,396 辆中。

目标环境字段必须统一：UAT 与 PRD 的订单客户编号、发运 Customer Number 和 Ship-to Party Number 当前均为 `270165`。不得继续使用旧 `UAT_220202` 模板。

1. 运维按 [[02 批量生产只读取数#A. 一次性候选全集导出范围]] 执行一条完整候选导出 SQL；现行范围使用 `g.e_type='S'`、`g.ship_to_party_no='270165'` 和当前快照日期窗口，不再使用 `MXASMIL%` 作为正式筛选条件。
2. 候选结果必须完整导出，不得受查询页面默认 1000 行限制。
3. 本地将候选结果与业务 18,449 个唯一 VIN 做交集；候选中的非业务 VIN 全部剔除。
4. 对交集结果逐 VIN 执行订单唯一性、有效发运指纹、模板必填字段和数量检查；任一业务 VIN 缺失时停止，不得默认认定为不迁移。
5. 先取 1 个已验证 VIN 执行 SQL 0、1，通过后取 20 个业务 VIN 验证查询和模板。
6. 正式批次建议约 200 个业务 VIN。
7. 多个业务 VIN 属于同一有效 OEM 订单时，必须放在同一批，避免重复创建订单号。
8. 阶段01与阶段03的已确认VIN属于同一OEM订单时，也必须归入同一次上游采购和发运导入。
9. 多个业务 VIN 使用同一发票时，建议同批，避免重复发票数据。
10. 归批只考虑阶段01和阶段03已经确认的迁移VIN；源订单或发票下的其他 VIN 不加入。

批次固化：批次号、业务 VIN 数、有效订单数、有效发票数、仓库分布和质量分布。

## 四、批前生产只读检查

按 [[02 批量生产只读取数]] 顺序执行：

```text
SQL 0：每个 VIN order_check=PASS
SQL 1：每个 VIN shipping_check=PASS
SQL 2：导出订单 Sheet
SQL 3：导出发运 Sheet
SQL 4：全部 qty_check=PASS
SQL 5：Gate In 参考对照
```

输入唯一 VIN 数必须等于 SQL 0、SQL 1、订单 Sheet 和发运 Sheet 的唯一 VIN 数。任何 VIN 缺失或多出都停止。

## 五、模板和 JSON

1. 复制单车 POC 已通过的采购/发运模板。
2. SQL 2 粘贴到订单 Sheet，一辆业务 VIN 一行。
3. SQL 3 粘贴到发运 Sheet，一辆业务 VIN 一行。
4. 不得补入源订单、源发票中的非业务 VIN。
5. 物料使用生产订单反查值；业务 Excel 物料为空不阻断。

转 JSON：

```text
POST /ops/smza-order/initGdsShippingData
file=<当前批次 Excel>
path=<UAT 应用服务器可写目录，末尾保留路径分隔符>
salesCompanyNo=5000
```

JSON 必须满足：

```text
salesCompanyNo = 5000
customerNo = 270165
deliveryItemVos[].customerNumber = 270165
JSON 唯一 VIN 集合 = 当前业务批次 VIN 集合
items[].qty = 同订单同物料的业务 VIN 数
```

## 六、UAT 批前目标库检查

当前批次所有订单号和业务 VIN 在全球库必须不存在：采购订单、车辆订单、车辆实例、GDS 发运、DN/ASN、待入库和库存记录。任一存在时停止并判断是否为前次部分落库；不得依赖 `duplicateIgnored` 继续。

## 七、导入采购和发运

每批只调用一次：

```text
POST /ops/smpOrder/save
Content-Type: application/json
Body=<当前批次 PurchaseAndShipping.json 完整数>
```

成功条件：外层 `success=true`、`successList` 数量等于有效订单数、`duplicateIgnored` 为空、`failed` 为空。超时、响应不明确或明细失败时禁止立即重试。

导入后逐 VIN 检查采购订单、物料、成功 GDS 发运、DN/ASN、待入库和目标仓链路。全球库新增 VIN 集合必须严格等于当前业务批次 VIN 集合，不能出现源订单中的其他 VIN。

## 八、Gate In

Gate In 模板字段：

| 字段 | 来源 |
|---|---|
| VIN | 业务 `VIN` |
| Quality | `NORMAL→1`；`QUALITY→2` |
| Gate In Date | 业务 `GATEINDATE` |
| 目标仓库 | 业务 `CURRENTWAREHOUSE#` 经 UAT 映射确认 |
| Notes | 当前批次号 |

TT 寄单日期、收提单日期和提单日期允许为空，不得补造。Gate In 日期、仓库和质量以业务清单为准。

放量前专项验证：1 辆 NORMAL 填 `1`，1 辆 QUALITY 填 `2`；两辆都完成采购、发运、Gate In 和库存查询后才能扩批。

## 九、批后验收

```text
业务确认 VIN 数
= 订单 Sheet VIN 数
= 发运 Sheet VIN 数
= JSON VIN 数
= 全球库新增 VIN 数
= Gate In 成功 VIN 数
= 最终库存 VIN 数
```

并确认全球库没有出现当前业务批次外 VIN。逐 VIN 追溯：业务输入、OEM 订单、成功发运、DN/ASN、Gate In、仓库、质量和最终库存。

## 十、立即停止条件

- `ship_to_party_no='270165'` 候选范围不能覆盖本次应迁业务 VIN，或覆盖率尚未完成业务确认。
- SQL 0 缺 VIN、无有效 OEM 订单或命中多个有效 OEM 订单。
- SQL 1 无成功关联发运，或出现多个不同业务指纹。
- 必要日期、物料、发票号或仓库映射缺失。
- Excel、JSON 或全球库新增 VIN 集合不等于业务批次 VIN 集合。
- 全球库出现源订单或发票下的非业务 VIN。
- UAT 已存在订单或 VIN。
- save 超时、响应不明、`failed` 或 `duplicateIgnored` 非空。
- DN/ASN、待入库、目的仓、Gate In 或最终库存状态错误。

## 十一、放量和生产边界

```text
1 个已验证 VIN → NORMAL/QUALITY 两车专项批 → 20 个 VIN → 每批约 200 个 VIN
```

每级必须完成采购、发运、Gate In 和库存验收后才能放量。UAT 扩批通过不等于生产就绪；生产仍需全量范围签字、主数据复核、批量性能验证、失败恢复方案、变更窗口和独立生产授权。
