# 工具链、发布与权限申请

## Jenkins SSH 发布超时

### 报错

```text
SSH: Connecting from host [saco219gitlab]
SSH: Connecting with configuration [sit-server02-Azure] ...
Failed to connect session for config [sit-server02-Azure]
java.net.ConnectException: Connection timed out
Build step 'Send build artifacts over SSH' changed build result to UNSTABLE
```

### 结论

Jenkins 的 Publish over SSH / Send build artifacts over SSH 步骤连不上目标服务器。

这是网络层超时，不是账号密码错误。账号或密钥错误通常会是：

```text
Auth fail
Permission denied
```

### 常见原因

- 目标服务器不可达，Azure VM 没启动或网络中断。
- 22 端口不通，NSG、防火墙、公司网络策略拦截。
- Jenkins 配置中的 host、port、用户名错误。
- 目标机 sshd 没启动。
- SSH 端口改了但 Jenkins 仍连旧端口。
- Jenkins 节点不在目标机白名单网段。
- Jenkins 出口 IP 变化。

### 排查命令

在 Jenkins 主机 `saco219gitlab` 上测：

```bash
ping <目标IP或域名>
telnet <目标IP> 22
nc -vz <目标IP> 22
ssh -v <user>@<目标IP>
```

如果 telnet / nc 到 22 也超时，基本就是网络、防火墙、安全组或服务器状态问题。

## IDEA 找不到 git.exe

### 报错

```text
Error: Failed to start Git process: Cannot run program "git.exe"
CreateProcess error=2, 系统找不到指定的文件。
```

### 原因

IDEA 想启动 `git.exe`，但系统找不到 Git 程序。

### 排查与修复

终端确认：

```powershell
git --version
where.exe git
```

如果找不到，安装 Git for Windows。

如果 Git 已安装但 IDEA 找不到，配置：

```text
Settings / Preferences -> Version Control -> Git -> Path to Git executable
```

填完整路径，例如：

```text
C:\Program Files\Git\bin\git.exe
C:\Program Files\Git\cmd\git.exe
```

然后点 Test。

## 数据库权限申请口径

### 只查数据

```text
账号：dingshuo
环境：SIT、UAT
库：develop_global_vehicle_junit、develop_global_vehicle
权限：SELECT
用途：SIT/UAT 环境问题排查
```

### 联调和测试数据维护

```text
账号：dingshuo
环境：SIT、UAT
库：develop_global_vehicle_junit、develop_global_vehicle
权限：SELECT、INSERT、UPDATE、DELETE
用途：SIT/UAT 环境联调测试、问题排查及测试数据维护
```

### 需要新增字段、删除字段、改表结构

更稳妥：

```text
账号：dingshuo
环境：SIT、UAT
库：develop_global_vehicle_junit、develop_global_vehicle
权限：SELECT、INSERT、UPDATE、DELETE、CREATE、ALTER
用途：SIT/UAT 环境联调测试、问题排查、测试数据维护、表结构调整（新增/修改/删除字段）
```

如果审批明确允许删除表/字段，也可补 `DROP`，但 `DROP` 敏感，最好单独说明。

## 每天必须有提交时的处理建议

如果当天没有代码改动，但必须有提交：

1. 最干净的是空提交：

```bash
git commit --allow-empty -m "chore: daily checkpoint 2026-06-12"
```

2. 如果要求必须有文件内容，优先做真实小修或补测试。
3. 不建议为了提交随意加无意义注释。

更好的提交内容：

- 修一个真实的小 bug。
- 补一个低依赖单元测试。
- 更新已有需求/排查文档。
- 删除未使用 import 或修正明显 typo。
