# 2026-07-11 DCS 墨西哥物料价格与采购单问题排查总结

## 今日结论

今天主要处理了墨西哥物料维护、采购价格同步和采购单保存三个问题。

整体链路：

`MDM 物料编码 → 本地组织车系/品牌 → 组织物料 → GDS/采购价格 → 采购单保存`

## 一、MX 物料维护接口空指针

### 现象

调用以下接口时，`MxVehicleMaterialInfoMaintenanceApplicationService.validationParam()` 出现空指针：

- `/vehicle/materialInfoMaintenance/mx/insert`
- `/vehicle/materialInfoMaintenance/mx/update`

原代码将 MDM 物料转换成 `materialCode -> brand`，并直接调用：

```java
v.getOrganizationSeriesID().getBrand().getCode()
```

全球仓库的 MDM 转换结果没有设置 `organizationSeriesID`。全球老接口能正常工作，是因为它只从 MDM 读取物料编码，品牌从本地车系取得。

### 修改

涉及文件：

- `MxVehicleMaterialInfoMaintenanceApplicationService.java`
- `MxVehicleMaterialInfoMaintenanceCommandVDO.java`

修改内容：

1. MDM 只用于校验物料编码是否存在。
2. `allMaterialCode` 从 `Map<String, String>` 改为 `Set<String>`。
3. `containsKey()` 对应改为 `contains()`。
4. 根据当前组织和请求中的 `series` 查询本地 `OrganizationSeries`。
5. 保存物料时，品牌取本地车系的品牌。
6. 请求字段 `brand` 改为可选，避免请求品牌与车系品牌不一致。
7. 保留 MX 特有字段 `version` 和 `vehicleKey`。

保存后的品牌来源：

`请求 series → 本地车系 → 车系 brand → 组织物料 brand`

## 二、MDM 物料不存在提示

错误示例：

`The vehicle material code info not exists.[LGRDSG49NCCDRT]`

含义：当前环境调用 MDM 后，返回的物料编码集合中不存在该编码。需要检查：

- MDM 是否已维护该编码；
- 大小写及前后空格；
- 当前环境是否连接正确的 MDM；
- MDM `getAll()` 接口是否返回该物料。

此阶段尚未进入本地车系和保存逻辑。

## 三、采购价格 Price Not Found

物料主数据存在不代表价格能够匹配。查价会依次尝试：

1. 客户价格包；
2. 国家价格包；
3. 客户采购价；
4. 国家采购价。

匹配维度包括：

- `pricing_party = sellerUuid`；
- 客户级 `pricing_domain = buyer customer_no`，不是 buyer UUID；
- 国家级 `pricing_domain = countryCode`；
- `currency`；
- `price_type`；
- 有效日期；
- 物料编码；
- 可用数量 `used_qty < max_qty`；
- 请求传年份时还会匹配年份。

本次确认的主要原因是订单币种与价格币种不一致。UAT 墨西哥采购价格币种为 `MXN`。

### GDS 价格同步和模拟

真实同步：

`POST /dcs-global-api/price/purchase/syncPriceFromGDS`

开发/UAT 模拟写入：

`POST /dcs-global-api/price-ops/uploadGDSPrice`

示例：

```json
[
  {
    "brandCode": "MG",
    "vehicleMaterialCode": "MCL2LC13K1CMBC",
    "countryCode": "MX",
    "fobPurPrice": "10000.00",
    "freight": "100.00",
    "insurance": "100.00",
    "currency": "MXN",
    "validFromTime": "2026-01-01",
    "validEndTime": "2026-12-31"
  }
]
```

该接口写入 `price_fob`、`price_freight`、`price_insurance`，定价方固定为：

`saicorga-niza-tion-5000-globalveh000`

注意：模拟接口会校验物料是否存在于 SMIL/5000 组织。

## 四、采购单保存 BigDecimal.add 空指针

### 现象

调用：

`POST /order/purchaseOrder/save`

堆栈：

`TradeOrderMaterialDao.java:183 → BigDecimal.add()`

### 根因

计算物料总金额时，下列费用字段尚未赋值：

- `marketingAmount`；
- `associationAmount`；
- `csrAmount`；
- `trainingAmount`。

原代码先执行 `unitPrice.add(null)`，之后才读取 `MaterialPriceQuota`，计算顺序错误。

### 修改

文件：`TradeOrderMaterialDao.java`

处理方式：

1. 四项附加费用先初始化为 `BigDecimal.ZERO`；
2. 存在 `MaterialPriceQuota` 时使用实际费用覆盖；
3. 最后计算总金额。

公式：

`materialAmount = (unitPrice + marketing + association + csr + training) × qty`

无价格配额时：

`materialAmount = unitPrice × qty`

本次数据：`10000 × 2 = 20000 MXN`。
