# 接口与数据核对

## 同步接口

```text
GET  /api/sync/latest?parkId=&configId=
POST /api/sync/manual
```

手动同步请求体可按场景传：

```json
{
  "parkId": 1,
  "configId": 2
}
```

## 设备接口

```text
GET /api/devices?parkId=&configId=
GET /api/devices/page?parkId=&configId=&keyword=&page=1&pageSize=20
GET /api/devices/stats?parkId=&configId=
GET /api/devices/nodes?parkId=&configId=
GET /api/devices/{sn}?parkId=&configId=
```

## 节点历史接口

```text
GET /api/devices/{sn}/history?address=0&configId=3&startDate=2026-06-16&endDate=2026-06-16
```

清理历史数据：

```text
DELETE /api/devices/history?configId=3&retainDays=30
DELETE /api/devices/history?parkId=1&retainDays=30
```

## 24 小时趋势接口

```text
GET /api/devices/{sn}/nodes/{address}/hourly-trend?date=2026-06-30&parkId=1&configId=2
```

取数规则：

- 横轴 00:00 到 23:00
- 每小时最多一个点
- 取该小时内最接近整点的一条 `sample_time`
- 没有数据的小时为空
- 今日未来小时为空
- 必须按当前设备、节点、园区/token 隔离

## 告警接口

## 数据量核对思路

当页面设备/节点数量看起来不对时，优先确认：

- 是按哪个 token / configId 统计
- 是否跨园区、跨公司
- 页面是设备数还是节点数
- 是否包含离线设备
- 是否取最新同步批次

常用 SQL 思路：

```sql
SELECT external_config_id, COUNT(*) AS device_count
FROM iot_device
GROUP BY external_config_id;
```

```sql
SELECT external_config_id, COUNT(*) AS node_count
FROM iot_node
GROUP BY external_config_id;
```

```sql
SELECT external_config_id, device_sn, COUNT(*) AS node_count
FROM iot_node
GROUP BY external_config_id, device_sn
ORDER BY external_config_id, device_sn;
```

## 历史查询慢的优化点

`iot_node_history` 已有关键索引，排查慢查询时优先看条件是否命中：

- `external_config_id`
- `park_id`
- `device_sn`
- `address`
- `sample_time`

历史查询建议始终带上：

```text
configId 或 parkId
sn
address
startDate / endDate
```
