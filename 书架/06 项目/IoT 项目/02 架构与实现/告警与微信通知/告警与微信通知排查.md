# 告警与微信通知排查

## 核心结论

页面看到“告警事件”，不等于微信已经送达。

告警链路大致是：

```text
同步设备节点值
  -> 告警规则判断
  -> 写入 iot_alarm_event
  -> 创建/执行 iot_alarm_notification_task
  -> 调用微信模板消息
  -> 成功后标记通知状态
```

## 事件是否已通知

```sql
SELECT id, event_type, device_name, node_name, message, notified, happened_at
FROM iot_alarm_event
ORDER BY happened_at DESC
LIMIT 20;
```

如果 `notified = 0`，说明页面有事件，但微信通知未完成或未成功。

## 联系人是否可接收

```sql
SELECT id, company_id, park_id, name, phone, enabled,
       openid IS NOT NULL AND openid <> '' AS wechat_bound,
       wechat_bound_at, deleted
FROM iot_alarm_recipient
WHERE deleted = 0 OR deleted IS NULL
ORDER BY updated_at DESC;
```

联系人需要满足：

- `enabled = 1`
- `openid` 不为空
- `deleted = 0`
- `company_id` 对得上
- `park_id` 为空表示公司级联系人，或等于事件的 `park_id`

## 日志关键字

```bash
cd /opt/iot-monitor
docker compose logs backend --since=2h | grep -i "wechat\|alarm"
```

重点看：

```text
No enabled bound alarm recipients
Wechat notifier disabled or incomplete
Wechat template message failed
Wechat template message sent
```

## 微信绑定回调排查

生成二维码后，前端会轮询：

```text
POST /api/alarm-recipients/{id}/wechat-bind-qrcode
GET  /api/alarm-recipients/{id}/wechat-bind-status
```

如果用户扫码/关注事件进入后端，日志应看到：

```text
POST /api/wechat/callback
```

排查命令：

```bash
docker compose logs -f backend | grep "/api/wechat/callback"
```

如果没有 `/api/wechat/callback`，优先查公众号后台：

- URL 是否配置：`http://<SERVER_HOST>/api/wechat/callback`
- 消息加解密方式是否为明文模式
- 服务器配置是否保存并启用
- `APP_WECHAT_APP_ID` 是否和当前服务号一致
- 用户是已关注扫码还是未关注扫码，两种都应该回调

## 清空事件记录外键问题

清空事件时要先删通知任务，再删事件，否则会被外键挡住。

正确顺序：

```text
iot_alarm_notification_task
  -> iot_alarm_event
```

验证：

```bash
docker compose logs -n 100 backend | grep "/api/alarms/events"
```

期望：

```text
HTTP DELETE /api/alarms/events?... -> 200
```

## 去重规则

相同园区、相同设备、相同告警类型，在 30 分钟内如果已经有一条已通知告警，后续相同告警不会重复发送。

## 联系人解绑与删除残留 openid

MyBatis-Plus 默认更新策略可能忽略值为 `null` 的字段。以下写法不保证数据库中的绑定字段被清空：

```java
recipient.setOpenid(null);
recipient.setWechatBoundAt(null);
recipientMapper.updateById(recipient);
```

解绑和删除联系人时应使用显式 SQL 将 `openid`、`wechat_bound_at` 更新为 NULL。排查历史残留：

```sql
SELECT id, name, enabled, deleted, wechat_bound_at
FROM iot_alarm_recipient
WHERE openid IS NOT NULL AND openid <> '';
```

已删除记录仍有绑定信息时，在备份并确认范围后清理：

```sql
UPDATE iot_alarm_recipient
SET openid = NULL,
    wechat_bound_at = NULL
WHERE deleted = 1;
```

二维码弹窗出现“已绑定”表示轮询已拿到 `BOUND`；弹窗不自动关闭属于前端交互，不代表绑定失败。
