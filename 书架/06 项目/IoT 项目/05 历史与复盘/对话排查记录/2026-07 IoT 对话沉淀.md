# 2026-07 IoT 对话沉淀

## 1. 服务号没有收到消息

问题：页面能看到告警事件，但微信服务号没收到。

沉淀结论：

- 页面事件记录只是说明写入了 `iot_alarm_event`
- 是否推送成功要看 `notified` 和通知任务状态
- 没收到优先查联系人是否启用、是否绑定 openid、微信配置是否完整、模板消息是否被微信接口拒绝
- 如果扫码绑定没有回调，重点看公众号后台是否启用了服务器配置

核心命令：

```bash
docker compose logs backend --since=2h | grep -i "wechat\|alarm"
docker compose logs -f backend | grep "/api/wechat/callback"
```

## 2. 清空事件记录外键报错

问题：清空事件记录时可能被 `fk_alarm_notification_event` 外键挡住。

结论：

- 先删 `iot_alarm_notification_task`
- 再删 `iot_alarm_event`

验证：

```bash
docker compose logs -n 100 backend | grep "/api/alarms/events"
```

## 3. 前端改动是否需要上传 dist

问题：改完前端后，是否需要上传 `dist`。

结论：需要。

- 前端改动需要 `npm run build`
- 新 `frontend/dist` 要发布到服务器或重建 frontend 容器
- 后端改动则需要重新构建 backend

发布：

```bash
cd /opt/iot-monitor
docker compose up -d --build frontend
```

## 4. 页面接口返回 HTML 导致 JSON 解析失败

问题：角色权限页面报 `Unexpected token '<'`，并且没有角色列表。

结论：前端请求漏了 `/api`，拿到的是前端 HTML 页面。

排查模式：

- 看到 `<!DOCTYPE` 基本就是请求到了前端入口页面
- 检查 service API 路径是否以 `/api` 开头
- 修复后重新 build 前端

## 5. 设备/节点数量核对

问题：两个 token 一共有多少设备和节点，页面显示是否准确。

排查方式：

- 按 `external_config_id` 分组统计设备数和节点数
- 确认页面统计的是设备、节点还是最新同步批次
- 防止跨 token、跨园区串数据

SQL 思路见：[[../../02 架构与实现/接口与数据/接口与数据核对]]

## 6. 历史查询慢

问题：设备历史查询接口慢，怀疑数据量大。

沉淀结论：

- 历史表数据量会增长很快
- 查询要尽量带 `configId/parkId + device_sn + address + 时间范围`
- 需要依赖复合索引
- 可以通过清理历史接口控制数据量

清理接口：

```text
DELETE /api/devices/history?configId=3&retainDays=30
```

## 9. 2026-07-12 微信联系人绑定与解绑排查

### 现象

- 微信服务号二维码回调最初提示 HTTP 返回非 200。
- 扫码后公众号回复绑定成功，但联系人页面仍显示未绑定或弹窗停留。
- 删除联系人后，数据库中的软删除记录仍保留 `openid`。
- 点击解绑后列表状态没有变化，也没有成功提示。

### 已验证结论

- 微信消息回调路径为 `/api/wechat/callback`，公网 URL 必须返回 HTTP 200。
- 新版微信开发者平台入口位于“域名与消息推送配置 -> 消息推送”。当前后端只适配 XML 明文消息，后台应选择明文模式。
- 公网域名、Nginx `/api/` 代理和后端回调路由已验证可达。
- 二维码弹窗检测到 `BOUND` 后会刷新状态，但原设计不会自动关闭，需要用户手动关闭。
- 解绑失败的根因是 MyBatis-Plus 默认更新策略忽略值为 `null` 的字段；仅调用 `setOpenid(null)` 后再 `updateById`，不会把数据库字段写成 NULL。
- 同一问题也会导致软删除联系人后遗留 `openid` 和 `wechat_bound_at`。

### 代码修改

- 后端新增显式 SQL 清空 `openid`、`wechat_bound_at`，用于手动解绑和删除联系人。
- 二维码弹窗状态增加语义颜色：已绑定为绿色，待绑定、过期、取消为红色。
- 解绑成功后增加绿色页面提示，说明已停止向该微信发送报警通知，3 秒后自动消失。

### 验证

```text
backend: mvn -q -DskipTests clean compile
frontend: npm.cmd run build
```

两项均通过。代码和本地前端构建产物已更新，但未部署、未重启线上服务、未提交或推送。

### 发布影响

- 后端必须重新构建并部署，解绑和删除时清理微信绑定才会生效。
- 前端必须重新构建并部署，状态颜色和解绑成功提示才会生效。
- 历史软删除记录如果仍有 openid，可在备份并确认范围后执行：

```sql
UPDATE iot_alarm_recipient
SET openid = NULL,
    wechat_bound_at = NULL
WHERE deleted = 1;
```
